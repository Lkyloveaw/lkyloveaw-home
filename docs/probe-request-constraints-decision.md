本文件是「探测请求约束」这张票的产出。
回答四个问题：**`redirect` 与 3xx 判定**、**scheme 白名单加在哪**、**`lastError` 脱敏边界**、**要不要防 SSRF**。

票：<https://github.com/Lkyloveaw/personal-wiki/issues/7>

## 1. `redirect` 与 3xx 判定（票的问题 1）

### 1.1 `redirect: 'manual'` —— 照票执行

实证：`follow` 会让跳转目标被请求 1 次，`manual` 是 0 次，且 `manual` 如实返回 302。
**决定：改 `'manual'`。** 这一条没有争议：跟随跳转等于让**被监控的系统**决定本服务接下来去打哪个地址，是把「探测」变成「任意地址请求器」的入口。

### 1.2 ⚠ 但 302 判 `up` 是一个真实的盲区（本票新实测）

`DEFAULT_OK_STATUS` 是 `200–399`，所以 **302 天然落在「可用」里**。实测构造了欺骗场景：

```
跳板（永远回 302） → Location: http://127.0.0.1:9/dead（目的地是死的）
manual 拿到的 status=302 → 判定 up（可用）★
实测目的地可达? false
```

**面板会把这个目标显示成「可用」，而它真正指向的系统根本连不上。**

这不是理论问题——`CONTEXT.md` 对三态的定义是「`up` = 状态码在 `expectStatus` 内」，而在 `manual` 之下，**3xx 不再能证明目标系统可用**（它只证明「有个东西回了 3xx」）。

### 1.3 决定：**不动默认判定表，把这件事标在配置与文档上**

候选方案与取舍：

| 方案 | 判断 |
| --- | --- |
| 把 3xx 从默认 `expectStatus` 里去掉（默认只认 2xx） | **否决**。会**静默改变所有既有部署的语义**：一份 `targets.json` 今天说某目标可用，升级后突然全变「异常」。运维会以为是系统挂了。这是最坏的一种改动方式。 |
| 把 3xx 一律判 `degraded` | **否决**，同上（也是静默变更）。而且 3xx 常是**正常的**（登录跳转、尾斜杠补全），一律标异常会制造噪音。 |
| 每个目标可配「是否跟随跳转」 | **否决（本票不做）**。这与 map 的「本次只修缺陷、不做新功能」冲突；且重新引入 §1.1 刚关掉的那条路。真需要就让人直接把 `url` 写成**最终地址**——那还更诚实。 |
| **保持 200–399 默认，但在文档与配置模板里显式写明** | **选它**。 |

具体：

1. `README.md` 的 `url` 字段说明与「探测语义」处写明：**探测不跟随跳转**；若目标依赖 3xx 才能到达最终系统，应**直接填最终地址**；默认 `expectStatus` 含 3xx，所以「回 3xx 的跳板」会被判为可用。
2. `targets.json` 的注释/示例里给一条 `expectStatus` 的显式用法，让人看得到「可以把 3xx 排除掉」这个手段。
3. **不引入新配置字段**。想排除 3xx 的人，写 `"expectStatus": [200]` 就够了——现有机制已经能表达。

> 这与 map Notes 里「**失败要显眼不要静默降级**」同一取向：宁可把语义写在明面上让人自己选，也不替所有既有部署偷偷改判定。

## 2. scheme 白名单加在哪、不合规怎么办（票的问题 2）

### 2.1 位置：`config.ts` 的 `normalizeTargets`，**与现有坏条目同一条路径**

不选「让服务拒绝启动」：现有风格是 **`console.warn` + 跳过**（缺 `id/name/url`、重复 id 都走这条路），而且 `targets.json` 是**人手工编辑**的，一个笔误让整个站点起不来（探测全停、面板空白）是过度惩罚。与「零账号允许启动」（账号票的决定）同一条原则：**配置有问题要显眼告警，但不进重启循环**。

### 2.2 规则：白名单 `http:` / `https:` + 拒凭证 + 必须可解析

草案已实测（18 条用例全过，见 §5）。三条规则：

1. **`new URL(url)` 必须解析成功**（拦 `''`、`'   '`、`'http://'`）。
   **根因实测**：无 scheme 的 `ledger.internal.example:8080` 会被解析成 `protocol='ledger.internal.example:'`、`host=''`——所以**只要查 protocol 白名单就能顺带拦住它**，不需要单独写一条「必须含 `://`」的规则。
2. **`protocol` 必须在 `{http:, https:}` 内** → 拦 `file:`/`gopher:`/`dict:`/`ftp:`/`javascript:`/无 scheme。
3. **`username`/`password` 必须为空** → 拦 `http://ops:hunter2@host/`（**只有用户名也算**，`https://user@example.com/` 被拒）。

**第 3 条与本 map 的字段收敛票直接咬合**：实测凭证 URL 落库的原文是
`Request cannot be constructed from a URL that includes credentials: http://ops:hunter2@…`——**带口令**。
出口脱敏（字段收敛票）负责**已经存进去的**；入口拦截（本票）负责**不再产生新的**。两边都要做，缺一不可。

### 2.3 不合规条目 = `console.warn` + 跳过，且警告文案必须可操作

沿用现有风格，但**警告里要说清「为什么不合法」**，否则运维只能猜：

```
[config] 跳过协议不支持的目标（只允许 http/https）：{"id":"x",...,"url":"file:///etc/passwd"}
[config] 跳过带凭证的目标 URL（会随错误原文落库）：{"id":"x",...}
```

**不给危险目标造「替代判定」**：跳过就是跳过，那条目标在面板上消失——比给一个 5000ms 超时的假象更诚实（真的探测它反而是在替它发请求）。

## 3. `lastError` 脱敏的边界（票的问题 3）

**决定：本票不重复实现脱敏，只做入口拦截；出口脱敏归「`/api/status` 字段收敛」票（已关闭）。**

理由：

- 脱敏规则已在那张票定死：**写入侧按「谁生成的」分流**——`probe.ts` 自有文案（`超时（>1500ms）`、`状态码 N 不在预期范围内`）原样保留；运行时异常走**类别码白名单**，且 **`?? e.message` 兜底必须删掉**（见 `docs/api-status-fields-decision.md` §4）。
- 本票若再定一套，就会出现**两份脱敏规则**，必然漂移。
- 本票的独立贡献是**在源头上不再产生新记录**（§2.2 第 3 条）。

**⚠ 依赖顺序**：本票落地时**必须先合字段收敛票的 `probe.ts` 改动**（删 `?? e.message` + 类别映射），否则入口拦掉凭证 URL 之后，其它形态的异常仍可能把原文写进库。两票在 `probe.ts` 同一处交叠。

## 4. 要不要防本机 / 云元数据（票的问题 4）

**决定：不做 SSRF 防护（地址黑名单），但**不是**因为「过度设计」，而是因为它与「内网可用性面板」这个用途直接冲突，且挡不住真正的风险面。**

### 4.1 实测：不是数据外泄通道

真起一个「内网服务」验证：探测确实能打到本机任意端口并拿到响应（`status=200`）。**但 `probe.ts:30` 的 `res.body?.cancel()` 只读 headers、主动取消 body**，所以：

- **拿不到响应体内容** → 「探测本机、把敏感数据读出来外泄」这条路，在当前实现下不通。
- 真正剩下的是**带副作用的请求**（探测打到一个「GET 就会执行动作」的管理端点）。

### 4.2 为什么不该加黑名单

1. **面板的用途就是探测内网地址。** `10.0.0.10`、`192.168.*` 正是它存在的理由；而 `127.0.0.1` 是**自托管场景的正当目标**（站点自己也在同一台机器上）。一张「内网地址黑名单」会把主要用途一起挡掉。
2. **挡不住。** 黑名单只能挡字面量：`http://0x7f.1/`、`http://2130706433/`、DNS 重绑定、以及**目标自己 302 到 `169.254.169.254`**（这正是本票把 `redirect` 改成 `manual` 的独立理由之一——改成 manual 之后，这条路**从根上关了**）。
3. **威胁模型不成立。** 目标清单是**运维自己手写**的，不是外部输入。**能改 `targets.json` 的人本来就有写文件权限**，加一层 SSRF 校验挡不住他，只会制造虚假的安心。

### 4.3 但必须做一件低成本的事：**把边界写进文档**

`README.md` 要明确：**`targets.json` 等同于「允许本服务主动请求哪些地址」的授权清单**，只放自己拥有/被授权探测的系统；**它不是不可信输入，别把它当沙箱**。
这条与 §1.2 的 3xx 说明放在同一处，一并交代探测语义。

> 这条与本票的 `redirect: 'manual'` 是配套的：**manual 关掉了「目标把我们引到别处」这条路**，这是本票对 SSRF 类风险的实际缓解，比黑名单更根本。

## 5. 可断言的回归用例

### 5.1 校验器（纯函数，**已实测 18/18 通过**）

**必须拒绝**：

| 输入 | 理由 |
| --- | --- |
| `file:///etc/passwd` | 协议白名单 |
| `gopher://127.0.0.1:70/x` | 协议白名单 |
| `dict://127.0.0.1:2628/x` | 协议白名单 |
| `javascript:alert(1)` | 协议白名单 |
| `ftp://example.com/` | 协议白名单 |
| `ledger.internal.example:8080` | 无 scheme（`protocol` 不是 http/https） |
| `http://ops:hunter2@127.0.0.1:9/` | 凭证 |
| `https://user@example.com/` | 只有用户名也算凭证 |
| `''` / `'   '` / `'http://'` | 无法解析 / 无主机 |

**必须放行（防误伤）**：

| 输入 | 理由 |
| --- | --- |
| `https://example.com/` | 常规 |
| `http://127.0.0.1:8080/health` | **自托管正当目标** |
| `http://10.0.0.10/` | **内网正当目标（面板的核心用途）** |
| `https://portal.internal.example:8443/a/b?x=1` | 带路径与查询 |
| `http://example.com/#frag` | 带 fragment |
| `https://例子.中国/` | 非 ASCII 域名 |

**「放行」那组是这条断言的价值所在**：一个过度的白名单会让面板探不到内网系统，而那正是它的用途。

### 5.2 跳转行为（真起跳板）

- 起一台永远回 302 的跳板 + 一台数请求次数的目的地。
- 断言：**目的地被请求 0 次**（`redirect:'manual'` 生效）。
- 断言：该目标记录的 `statusCode === 302`（如实返回，不吞）。
- 回归：默认 `expectStatus`（200–399）下 302 判 `up`——**把 §1.2 的已知盲区钉成一条显式断言**，而不是留成「不知道会怎样」。将来谁改判定表，这条断言会提醒他这是**有意的**语义。

### 5.3 落库侧

- 喂一个凭证 URL（**绕过配置校验直接构造**，验证纵深防御）→ 断言历史库里**不出现带口令的原文**（依赖字段收敛票的脱敏）。

### 5.4 配置层

- 提交一批坏条目 → 断言：**服务正常启动**、坏条目被跳过、**每个坏条目都有一条说明原因的 `console.warn`**（不是静默跳过）。
- 断言 `targets.json` 里现有的 3 个演示目标**全部照旧被接受**（不误伤）。

## 6. 实现落点

| 文件 | 改动 |

**⚠ 与其它票的顺序**：`src/probe.ts` 同时被「字段收敛」票（错误脱敏）与本票（`redirect`）修改。**先合脱敏，再改 `redirect`**，或一次改完但把两件事分开成两个 hunk，避免一个 revert 带走另一个。

## 7. 边界

- 本票**不改**三态判定表与 `DEFAULT_OK_STATUS`（§1.3）。
- 本票**不实现**错误脱敏（§3，归字段收敛票）。
- 本票**不做**地址黑名单 / SSRF 防护，只改 `redirect` 并把边界写进文档（§4）。
- 本票**不做**「每目标可配是否跟随跳转」（§1.3 已否决）。
- 本票**不改** `probe.ts` 的 `res.body?.cancel()`（只读 headers 是有意设计，且是本票 §4.1 结论的前提）。
