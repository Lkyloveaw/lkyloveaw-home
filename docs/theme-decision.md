## 0. 一句话结论

**全站 = B 暖色纸墨的浅色一套**（米白纸 + 暖墨字 + 赭石强调），`public/style.css` 里**恰好一个 `:root`**、
**没有** `prefers-color-scheme` 块；A 与 C 出局，深色那套整个丢掉。

| 问题 | 结论 |
| --- | --- |
| 赢家 | **B 暖色纸墨**（用户从三套里挑的） |
| 深浅 | **只保留浅色**；深色模式去掉（用户定稿时加的） |
| 落在哪 | `public/style.css` 的唯一 `:root`（13 个颜色 token 全换） |
| 断言怎么跟 | `scripts/style-check.mjs`：`rootCount 1`、13 色齐全、**没有 media 块**、**颜色只住两处** |
| 预览怎么收 | **没进过 main**：整份住在抛弃式分支 `prototype/theme-3way`（一手证据），主分支不留一行 |

## 1. 取值（就是产品里现在那 13 个）

| token | 值 | 用途与理由 |
| --- | --- | --- |
| `--bg` | `#f6efe2` | 米白纸 —— 「纸墨」这个词的本体 |
| `--bg-soft` | `#efe4d1` | 纸上的浅底块（`code` / 输入框 / `notice`） |
| `--bg-card` | `#fffaf0` | 卡片比纸**亮一点**，才浮得起来（不能比纸暗，暗了像凹陷） |
| `--border` | `#dbceb6` | 暖灰边框（冷灰压米白会显脏） |
| `--fg` | `#2b2318` | 暖墨 |
| `--fg-dim` | `#5d5343` | 次要文字 |
| `--fg-faint` | `#6f6452` | 最弱文字（当**文字**用要过 4.5:1；当边框用不用） |
| `--accent` | `#8f3f18` | 赭石：链接 / 当前项 / 主按钮底 |
| `--ok` | `#3f6b2f` | 橄榄绿（荧光绿压在米白上会糊） |
| `--warn` | `#7a5510` | 琥珀压深 |
| `--bad` | `#a32b1f` | 砖红压深 |
| `--unknown` | `#cdc0a6` | 无数据格的**填充色**，不是文字色 |
| `--on-accent` | `#fff8ee` | 暖白压深赭石（亮赭石底压白字只有 3.x:1，过不了） |

排版的 11 个 token（`--radius` `--wrap` 字体/字号/行高/`--measure-prose`）**一个没动**。

## 2. 与 A（今天那套）的差异清单（具体，不是「差不多」）

A = 冷灰底 `#0f1115` / 亮蓝 `#5b9dff` / 荧光状态色；B = 暖纸底 / 赭石 / 压深的状态色。

| 维度 | A（旧） | B（新） | 为什么 |
| --- | --- | --- | --- |
| 底色 | `#0f1115` 冷灰 →（浅色下 `#f7f8fa` 冷白） | `#f6efe2` 米白 | 整体从「屏幕」搬到「纸」：这是选型的主因 |
| 强调色 | `#5b9dff` 亮蓝 / 浅色下 `#1a66d8` | `#8f3f18` 赭石 | 蓝在冷底上「和底同族」，赭石在米白上才是印刷里那点重量 |
| 卡片与底的关系 | 卡片比底**亮**（暗色下的浮起） | 卡片 `#fffaf0` 比纸亮 | 方向一致，只是从「提亮一点」变成「纸上的白卡」 |
| 状态三色 | 荧光绿/琥珀/红（`#35c46b` `#e8b13a` `#f2564d`） | 橄榄/琥珀/砖红，全部压深 | 荧光色压米白只有 3.x:1；压深后最差 6.02:1 |
| 文字三档 | 冷白 `#e6e9ef` 起 | 暖墨 `#2b2318` 起 | 暖底配冷白会「发青」 |
| 主按钮 | 深字压亮蓝 | 暖白压深赭石 | `--on-accent` 的取法**正好相反**：亮蓝底的深字 → 深赭石底的暖白 |
| 深浅两套 | 暗色默认 + light 覆盖（2 个 `:root`） | **只有浅色**（1 个 `:root`） | 见 §3 |

## 3. 为什么去掉深色模式（以及代价）

用户定稿时的原话是「b 浅 把深色模式去掉吧」。按字面落地：**站点只剩浅色**，系统是深是浅都不再影响配色。

**换来的**：

- 主题真正是「一份」：一个 `:root`、13 个值。此前「哪一套是产品」永远有两个答案（默认 + 覆盖），
  二者的对比度要分别算、分别维护（`style-check` 原本就为这两套各跑一遍）。
- 选型不再打折：三套 × 深浅是**六**个组合，人只能对着图挑一个；现在挑出来的那套就是屏幕上那一套。

**代价（记录在案，不粉饰）**：

- `style.css` 开头原本写着「深色为默认（内网运维面板多在暗环境看）」—— 那个判断现在被推翻了；
  暗环境里看这个站（尤其面板/管理台）会比以前刺眼。
- 想回到深色不再是「加个覆盖」：得把 13 个值重新调一遍并重跑断言（这次的深色取值还在分支上，可以拿来当起点）。
- 打印块保留（见 §6）：屏幕已经是纸色，但打印仍强制纯白/黑字（省墨 + 对比最大）。

## 4. 断言怎么跟着改（`scripts/style-check.mjs`）

这不是「改脚本去迁就实现」—— 恰恰相反：**把决定写成断言**。四处改写 + 两条新增：

| 断言 | 旧 | 新 |
| --- | --- | --- |
| `:root` 数量 | 「恰好两个（暗色定义 + light 覆盖）」 | 「**恰好一个**」 |
| 颜色 token | 「每个颜色都在 light 里被覆盖（13 个）」 | 「唯一的 `:root` 里有 **13 个颜色 token**（一份完整的主题）」 |
| 排版 token | 「light 覆盖里没有混进排版 token」 | 「11 个排版/形状 token **也在同一个 `:root` 里**」 |
| 对比度 | 对 `dark` / `light` 两套各跑一遍 19 对 | **只跑一遍** 19 对（唯一那套） |
| **新增** | — | 「CSS 里**没有** `@media (prefers-color-scheme …)` 块」—— 把「深色模式已去掉」钉住 |
| **新增** | — | 「颜色 token 只定义在**唯一的 `:root` 与打印块两处**」—— 别处写死一个颜色 = 第二份没人盯着的真相 |

⚠ 第一条新增断言匹配的是**规则**（`@media … prefers-color-scheme`），不是那串字 ——
注释里提到它不犯规（`style.css` 的开头注释现在正提它）。

## 5. 验收

| 断言 | 结果 |
| --- | --- |
| `npm run check:style` | **54 项全绿**（从 71 项降下来，是因为对比度不再跑两遍、`light 覆盖`那几条并进了「唯一 `:root`」） |
| 19 对前景/背景 | **全部 ≥ 4.5:1**；最差 **4.61:1**（`--fg-faint` on `--bg-soft`） |
| 13 个 token | 全在唯一的 `:root` 里；颜色定义总数 22 = `:root` 13 + 打印 9（没有第三处） |
| 原型阶段的证据 | 三套候选共 **114 对**（3 × 19 × 2 模式）当时全过 —— 最差 4.54:1（A 的 `--fg-faint` on `--bg-card`） |

## 6. 预览的下场：**没进过 main**

与 map Notes 13 的「选定后删除」等价，但更彻底：预览**整份**住在抛弃式分支 `prototype/theme-3way`
（提交 `7258567`：`src/theme-preview.ts` + `server.ts` 的一条路由 + 两个 scripts + `package.json` 两条命令）。
**主分支一行都没进来过**，所以没有「删干净」这一步可漏；要看当初的三套候选，`git checkout prototype/theme-3way` 即可。

那是**一手证据**，不是备份：（a）三套候选的完整取值与差异说明，（b）114 对的逐对比值，
（c）「真片段」渲染法（把产品真页面函数吐出的 `<main>` 取出来摆在一页上），（d）`?only=` 分块与 `SHOTS=1` 截图。

## 7. 连带影响（落地时一起改，否则验收是假的）

1. **`CONTEXT.md:122`** 说「全站只有一份颜色 token（`:root` 暗色 + `light` 覆盖）」—— 已改成「一个 `:root`、浅色单套」，
   并补了 **主题（theme）** 词条（map Notes 15 点名要在落地时补）。
2. **`docs/visual-prototype-decision.md` §8**（#21 定稿）说「`:root` 两处：暗色定义 + light 覆盖」——
   已加一行修订说明指向本文（原文保留，见修订行）。
3. **`docs/admin-console-ia-decision.md` §1.1** 拿 `prefers-color-scheme` 当「禁用 JS 也能用」的例证 ——
   那个例子随着这次改动失效了，已换成打印样式（同样是纯 CSS 的取向）。
4. **登录页**：它不走 `layout()`、自己写 `plane-data`，但**吃的是同一份 token** → 自动变米白纸，不需要单独改。
5. **`status.js`**：只加类名、不写颜色 → 不受影响。
6. **打印块**：保留。屏幕已是纸色，但打印仍强制 `#ffffff` / `#000000`（省墨 + 对比最大），
   并继续把纸面 token 改在 `body` 上（全站只有一个 `:root` 这条纪律连打印也不破）。

## 8. 边界（本文不定）

- **不做运行时切换**：站点设置里换主题、偏好持久化（map Notes 4 已排除）。
- **不改排版**：#45 定稿的两套平面（终端等宽化 / 纸感阅读化）与 68ch 窄栏一个字节不动。
- **不重调组件级细节**：阴影、`color-mix` 的透明度、`backdrop-filter` 都沿用原值；
  米白纸上如果某个组件显得平，那是**后续的观感票**，不是这次选型的漏项。
- **不做深色**：想恢复要按 §3 重调 13 个值并重跑断言，那是新的一票。
