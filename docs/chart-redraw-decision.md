# 曲线实时重绘：实现决定

本文件是「曲线实时重绘」这张票的产出。
回答六个问题：**映射逻辑放哪**、**值域怎么定**、**横轴范围**、**断开点**、**空状态**、**「无曲线」能不能切回来**。

票：<https://github.com/Lkyloveaw/personal-wiki/issues/8>

已确认的前提（不再论证）：曲线也跟着 30 秒重绘，手写 SVG path，**不加图表库**。
前置票：「/api/status 字段收敛」（已关闭）——本票的字段名以 `docs/api-status-fields-decision.md` 为准。

---

## 0. 现状（读码 + 实测确认）

- 曲线现在是**服务端渲染的内联 SVG**（`src/charts.ts`）。页面加载后就冻结。
- `public/status.js` 的 `tick()` 每 30 秒 `fetch('/api/status')`，`paint()` 只更新 `.dot` / `.uptime` / `.kv dd[0..1]` / `.target-error` / `.js-generated`——**对 SVG 的更新命中数为 0**。实测确认。
- 数据通路已存在：`/api/status` 返回 `latency` 与 `timeline`（字段收敛票保住了它们，并固定了形状：`latency[]={at,avgLatencyMs}`、`timeline[]={at,status,latencyMs}`、`overview[]={at,up,total}`）。
- 服务端画线的核心是 `charts.ts` 的 `linePath(values, w, h, pad, xAt, xRange)`：
  - `values` 里**非 null、有限、≥0** 的点要 **≥2 个**才画线，否则返回 `null` → 调用处出 `.chart-empty`；
  - `span = max-min < 1 ? max(max,1) : max-min`（**退化保护**）；
  - `useTime` 需同时满足 `xAt` 非空、`xRange` 非空、`xRange.max > xRange.min`，否则退化成等距排布；
  - 遇到 `null`/非法值就 `open=false` **断开**，不连线。
- 配套还有 `areaPath()`（渐变填充，从 `d` 里正则抠 x 坐标闭合）、`hash()`（渐变 id，防同页串色）、`axisLabel()`（横轴时间标注）。
- `views.ts` 还在卡片里渲染 `timelineBar(timeline)`（`.tl-cell` 小方块串）——**它也是冻结的**，见 §7 边界。

## 1. 映射逻辑放哪：**把 `linePath` 搬到前端**，而不是服务端算好点

票把选项写成「服务端算好点 / 前端复制一份」，并假设前者响应更小。**实测与推演都表明这个假设是反的**：

1. **响应只会更大。** `latency` / `timeline` 的原始数值**已经**在响应里了（字段收敛票的明确决定，就是为了本票）。再服务端算一份像素坐标，等于同一批数据发两遍。
2. **服务端算不出来。** y 值域依赖**客户端自己的状态**（见 §2 的「只扩不缩」），x 范围依赖**整页共享**的 range（见 §3）。服务端不知道客户端当前的域，没法替它算点。
3. **会污染刚定好的公开契约。** 字段收敛票刚把 `/api/status` 定成**纯数据**（`at`/`avgLatencyMs`）。往里加 `x`/`y`/`d` 就是把**表现层几何**塞进公开契约，等于把那张票的决定推翻。

所以：**前端要有一份 `linePath` 的映射实现。**

### 1.1 怎么防「两份实现漂移」——这是本票的真正风险

项目**没有前端构建步骤**（`public/` 直接静态服务），`charts.ts` 是 TS（`rootDir: src`），前端是 classic script。两边**无法共享同一个模块**：`rootDir` 与 `allowJs:false` 决定 `src/charts.ts` 不能 import `public/` 下的文件，强行共享会破坏构建。

**决定：把可移植的几何核心抽到 `public/chart-path.js` 一个文件**（`public/` 直接被静态服务，无需构建），`src/charts.ts` 保留自己的 TS 实现供 SSR；**用一条「同一份输入，两边必须产出同一个 `d`」的交叉断言把漂移变成红灯**。

这条断言**已实测可跑通**（草案 + 一次性测试验证后删除），比空口承诺强：

- **服务端**：`latencyChart(pts, 520, 110, xRange)` → 从渲染出的 SVG 里抠出折线 `d`。
- **前端**：在 `node:vm` 沙箱里跑 `public/chart-path.js`，调用同一函数。
- 断言：两个 `d` **字符串完全相等**；空状态判定一致；`areaPath` 一致；渐变 id 哈希一致。

实测结果（7 组数据：常规上升 / 含失败断开 / 全等值 / 含 0 / 单点 / 空 / 两点）：

```
=== 1. 服务端 d vs 前端 d ===         7/7 PASS
=== 2. 空状态判定一致 ===              7/7 PASS
=== 3. 面积填充一致 ===                4/4 PASS
=== 4. 渐变 id 哈希一致 ===            4/4 PASS
=== 5. 可用率曲线一致 ===              1/1 PASS
```

> ⚠ **踩坑记录（写测试时必读）**：`package.json` 有 `"type": "module"`，所以 Node **把 `public/chart-path.js` 当 ESM**，`require()` 它只会拿到 `{}`，UMD 头的 `module.exports` 分支**永远不执行**。测试必须用 `node:vm` 造一个「没有 `module`、只有 `globalThis`」的沙箱——那恰好就是浏览器里 classic `<script>` 的环境。
> 顺带一个坑：从 SVG 里抠 `d=` 的正则要写成 **`/ d="([^"]*)"/g`（带前导空格）**，否则会把 `<linearGradient id="lg82322460"` 里的子串也算成路径——实测该正则会命中 3 条，其中 `[0]` 是渐变 id 的残片。

## 2. 值域策略：**冻结 + 只扩不缩 + 最小跨度**（本票最重要的一节）

### 2.1 先量化问题（实测）

造一段真实感的延迟史（基线 142–269ms，第 25 个点是一次 5000ms 尖峰），复刻 `linePath` 的 y 映射，模拟每次 30 秒刷新时窗口右移：

```
=== 策略 A：每帧重算 min/max（服务端现在的做法，前端照搬）===
end=10 min= 186ms max= 269ms 跨度=  83  老点最大 y 位移 = —
end=15 min= 143ms max= 269ms 跨度= 126  老点最大 y 位移 = 33.4px ★明显跳动
end=26 min= 142ms max=5000ms 跨度=4858  老点最大 y 位移 = 95.4px ★★大幅跳动
策略 A 最坏位移 = 95.4px（图高 110px，即 87% 的高度）
```

**尖峰进入窗口的那一瞬间，图上所有老点被压到顶部一小条里，一次位移 95px = 图高的 87%。** 票里担心的「曲线纵向跳动」是真实且严重的。

### 2.2 ⚠ 第一版草案（nice 阶梯）被实测推翻（记录在案，不要重走）

第一版草案是「向外取整到 1-2-5 阶梯 + 最小跨度」。实测：

```
帧  min  max   原始y位移   nice值域        nice下老点位移
 3  142  269      0.0px    [   0, 200]        0.0px
 4  142 5000     43.6px    [   0,5000]       94.1px   ★
 8  150  300     31.4px    [   0, 200]       94.1px   ★
同一个老点(200ms)最坏位移：原始值域 43.6px  vs  nice 值域 94.1px
```

**比不做还差，而且多了一个新缺陷**：阶梯向下取整会把数据挤出值域（第 8 帧 max=300 但域上限只有 200），点在图外。所以「阶梯化」不是解法。

### 2.3 根因

**只要值域跟着数据走，数据极值一移动，整条线就得重新缩放。** 尖峰进窗口要缩一次，尖峰离开窗口又要缩回来——**两次跳动**。阶梯化只改变跳动的粒度，不消除它。

### 2.4 决定

**值域在页面生命周期内「只扩不缩」，并由服务端把初始值域写进 DOM 交给前端。**

规则（按顺序）：

1. **服务端把初始值域算好、写进 DOM**：给图表容器加 `data-y-min` / `data-y-max`。前端首帧直接采用它 → **首次重绘与 SSR 完全一致，页面加载时不会跳一下**。
2. **最小跨度下界**：`span ≥ max(20% × max, 10)`。防的是「窗口里只有 2–3 个点、值域极窄，线贴着边抽动」——`load` 后头几十秒正是这个状态。
3. **只扩不缩**：新数据超出当前值域时才扩（扩到刚好容纳，可按 1-2-5 向上取整以**量化**扩张次数，但**只许向上**，绝不向下取整），**数据变小时值域不动**。
   - 消除了「尖峰离开窗口 → 又跳回来」这**第二次**跳动。
4. **越界点夹到边缘**：万一有点在域外（例如页面开了很久、基线整体抬升），y 夹进 `[pad, h-pad]`，**画在边缘而不是画出 viewBox**。曲线图的 `figcaption` 本来就写着「峰值 N ms」，所以夹紧不等于撒谎。

**保留下来的那一次跳动是诚实的**：数据真的换了量级，服务端重新加载页面也会这样显示。本策略**只消除抖动（jitter）与回跳，不假装消除量级变化**。

**代价（明说）**：页面开很久后值域可能被一次历史尖峰撑大过、且不再缩回，曲线会显得偏平；刷新页面即重新计算。个人站面板的页面生命周期短，接受这个代价。

> 为什么不是「用 p95 之类的稳健统计量」：那会把尖峰**裁掉**，而延迟曲线的尖峰恰恰是最该看见的东西，与 `CONTEXT.md` 里「异常断开不画成 0」同一取向——**宁可标出真实峰值，也不要平滑掉异常**。

## 3. 横轴范围：**每次重绘都重算整页共享的 range**

服务端的既有不变量（`views.ts` 注释）：「同一页所有曲线共用一个横轴范围，否则各卡片的曲线会各自铺满宽度，时长看起来一样长」。

**决定：前端每次 tick 重新计算一个共享 `xRange`**，取**所有**目标 `latency[].at` ∪ 所有 `timeline[].at` ∪ `overview[].at` 的 min/max，然后**一次性**应用给所有曲线（含整体可用率那一条）。

- 不重算是不行的：新数据点在最右端，x 轴必须向右延展。
- x 轴延展是**单调、平滑、方向单一**的（时间只向前），**不产生 §2 那种抖动**，所以这里可以放心跟随数据。
- `axisLabel`（左右两个时刻 + 覆盖时长）与 `figcaption` 里的平均/峰值文字**必须一起更新**，否则会出现「线变了、标注还是旧的」这种自相矛盾的界面。

---

## 4. 断开点：**原样复刻，不做「优化」**

`linePath` 的 `open=false` 语义必须逐字搬过来：遇到 `null`/非有限/负值 → 断线；下一个有效点用 `M` 起新段。

这是 `CONTEXT.md` 明确记录的领域约定（**异常断开**：失败处断开，不画成 0，因为 0ms 会让曲线看起来「更快了」）。**任何「用前值补齐」或「插值连接」的写法都是错的**，必须在 review 里挡掉。

---

## 5. 空状态 + 第 6 问（能不能切回来）：**用「整块重建」保证双向可切**

**决定：每次重绘直接重建图表容器的 innerHTML，空态与非空态走同一条渲染路径。**

理由：空态与非空态的 DOM **结构不同**（`.chart-empty` 是个 `div`，正常态是 `figure + svg + figcaption + .chart-axis`）。若按「原地改属性」实现，就会出现：

- 一开始没数据 → 渲染了 `.chart-empty`；
- 后来有数据 → 需要**新建**整个 `figure`；
- 后来又没数据（例如目标被禁用/清库）→ 需要**删掉** `figure` 换回 `.chart-empty`。

「只更新 path 的 `d`」这条路**天然覆盖不了**第 2、3 步——这正是票里第 5、6 问指出的陷阱。整块重建让两个方向都自动成立，一次锁死。

**代价可接受，且已实测过量级**：单卡片曲线每次重建 ≈ 1 个 `figure` + `svg` + 2 个 `path` + `defs/gradient` + `figcaption` + `axisLabel`，**几十个节点、30 秒一次**，对浏览器完全无感。不是每帧渲染，不需要 diff。

**配套落点**：现在图表容器**没有任何稳定钩子**（卡片上只有 `data-target`，图表本身无标识），前端无从定位要替换哪一块。→ 在 `charts.ts` 给容器加 `data-chart` 标识（`latency` / `uptime`），前端按 `closest('[data-target]')` + `[data-chart]` 定位。这是本票必须一并改的落点。

## 6. 实现落点

| 文件 | 改动 |
| --- | --- |
| `public/chart-path.js`（新） | 可移植几何核心：`linePath` / `areaPath` / `hash` / 值域策略。classic script，挂 `globalThis`（与 `status.js` 同风格，无构建步骤） |
| `public/status.js` | `paint()` 增加曲线重绘：算共享 `xRange`、按 `data-y-min/max` 取初始值域并「只扩不缩」、整块重建每个 `[data-chart]` 容器、同步 `figcaption` 与 `axisLabel` |
| `src/charts.ts` | 图表容器加 `data-chart` 与 `data-y-min` / `data-y-max`；几何逻辑保持与 `chart-path.js` 等价（由 §1.1 的交叉断言保证） |
| `src/views.ts` | `status.js` 之前引入 `chart-path.js`（`<script src="/chart-path.js" defer>`，顺序在前） |
| `src/server.ts` | **不动**。重绘只读 `/api/status`，不需要新端点（字段收敛票已把所需字段留在响应里） |
| `scripts/e2e-check.mjs` | 见 §7 的交叉断言与回归用例 |

**闸门白名单必须同步**（已关闭的闸门票定的白名单是精确匹配）：`/chart-path.js` 要加进 `src/server.ts` 的白名单，否则**未登录时登录页拿不到它**、登录后也可能被 401 拦掉。**这是一个容易漏的联动点。**

## 7. 可断言的回归用例

1. **交叉断言（本票最重要的一条）**：同一份输入，服务端 `latencyChart()` 渲染出的折线 `d` 与 `node:vm` 里 `chart-path.js` 算出的 `d` **完全相等**；空状态判定一致；`areaPath` 一致；渐变 id 一致。覆盖：常规 / 含断开 / 全等值 / 含 0 / 单点 / 空 / 两点。**没有这条，「两份实现」迟早漂移。**
2. **形状断言**：每个曲线容器带 `data-chart` 与 `data-y-min`/`data-y-max`；`data-y-min ≤ data-y-max` 且域含住该图所有点（除非页面开了很久，见 §2.4 第 4 条）。
3. **值域不抖动断言**（纯函数，可不启浏览器）：喂 §2.1 那串含尖峰的序列，断言「同一个老点的 y 位移」在值域策略下**恒为 0**（直到发生一次真实扩张）——即**没有回跳**。这是防 §2.2 那种「修得比不修还差」的回归。
4. **断开不被连上**：含 `null` 的序列，渲染结果里必须有 `M`（新段起点），且**不得**出现跨越失败点的连线。
5. **空态双向可切**：给「空 → 有数据 → 又空」三次输入，断言 DOM 在 `.chart-empty` 与 `figure` 之间**能来回切**（防「第一次有数据后永远不再显示无曲线」）。
6. **`/chart-path.js` 匿名可取**：闸门落地后仍在白名单里（`GET /chart-path.js` 不该 302/401）。

> **顺序提醒**：本票的 §2 值域改动会改变**服务端**渲染出的 `data-y-min/max` 语义，而 `/api/status` 的字段形状由字段收敛票决定、本票不改。两票在 `src/charts.ts` 与 `public/status.js` 上有交叠，实现时**先合字段收敛票的字段名**再落本票。

## 8. 边界

- **不**引图表库（已确认硬约束）。
- **不**改 `/api/status` 的字段形状（字段收敛票的产出）。
- **不**做浏览器端的缩放/平移/十字准星等交互——本票只解决「跟着 30 秒刷新重绘」。
- **`timelineBar`（`.tl-cell` 状态条）不在本票范围**：它同样是冻结的，票的标题与问题都限定在「曲线」。但它确实是**同一类缺陷**，且字段收敛票已经把 `timeline[]` 留在 API 里、本票又把共享 `xRange` 算好了——真要做，成本很低。**建议在 `## 进度` 里登记为新票候选，由主理人决定**，不在本票顺手做（避免把票做成两件事）。
- 曲线数据的**保留上限**（`timeline` 60 点 / `latency` 120 点）由字段收敛票定，本票不改。
