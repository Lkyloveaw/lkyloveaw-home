## 0. 结论一句话

**主题不用切** —— #60 的收口里已经落地（`style.css` 的 `:root` = B 暖色纸墨浅色单套，`check:style` 54 项 + e2e 501/501）。
**侧栏切 2 张票**，一次纵深、一次收口：

```
① 侧栏长出来（views + style.css + style-check + e2e，一次原子交付）
      └─→ ② 收口（两句今天就已经是假的话 + 决定书回填 + 全量回归记录）
```

**2 张，不是 4 张**：四批那个先例切的是一个**从零长出来的子系统**（文章后台：格式 / 搬库 / 写路径 / 媒体 / 收口）。
侧栏不是子系统，是**一个 `layout()` 分支** —— 六个页面在**同一次**改动里长出侧栏，没有可交付的中间态。理由见 §1。

## 1. 为什么不是四批，也不按文件切

| 判据 | 结论 |
| --- | --- |
| **能独立验收的最小边界** | 侧栏是一次全量回归就能验完的东西：六个路由 + 四个反例（403 / 非管理台 / 编辑态 / 窄屏）。它的下界就是「一次回归」，再切就是切文件 |
| **「逐页」切不了** | 六个页面共用**同一个** `layout()` 分支：`adminSection` 一加、分支一落，六页同时长出侧栏。按页切会得到六次同形状的改动 + 六次全量回归，且中途三个页面有侧栏、三个没有 —— 那不是可交付状态，是坏掉的界面 |
| **「基座（token）」与「外壳（class + 分支）」不能分开** | `style-check` 有两条方向相反的约束：视图里渲染的类名**必须**在 CSS 里有定义（先落 markup → 红），而先落 CSS 又会长出**死契约**（本仓明令清掉的形状，见 `panel-check.mjs` 的 `.tl-*` 两条） |
| **不按文件切** | 「改了 `views.ts`」不是一张票：它不可验收，也不可单独上线。判据是**垂直切片** —— 每张票交付一个用户看得见的、能独立验收的能力 |

## 2. 两张票的详细边界

### 票① 侧栏长出来（含它自己的断言）

**交付**：管理台六个页面左长出 `#59` 定稿的侧栏 —— 运维（概览 / 目标 / 账号 / 备份 / 设置）+ 内容（文章），
当前项高亮，≤720px 折成条目条，打印时隐藏。**站点其余部分在视觉与行为上零变化。**

**落点**（`#59` 决定书 §2/§7 是契约，这里只是清单）：

| 文件 | 改什么 |
| --- | --- |
| `src/views.ts` | `LayoutOptions.adminSection?: AdminSection`（六值闭合枚举）；`layout()` 加**一个分支**（`<main class="wrap admin-shell">` + `<nav class="admin-side" aria-label="管理台导航">` + `.admin-main`）；侧栏片段函数（分组表写死在这里）；六个页面函数各自的 `layout()` 调用补自己的 `adminSection`（290 / 453 / 546 / 644 / 787 / 1395 六行）。**`nav()` / `planeOf()` / `forbiddenPage()` 不动** |
| `public/style.css` | `:root` 加 `--wrap-admin: 1140px`、`--side-w: 220px`（非颜色）；五个类名 `.admin-shell` `.admin-side` `.admin-side-group` `.admin-side-group-label` `.admin-main` + 高亮规则 `.admin-side a[aria-current="page"]`；720px 断点里折行（`.admin-side` 横排、组标签各起一行）；打印块里隐藏 `.admin-side`、`.admin-shell` 退回 `display: block` |
| `scripts/style-check.mjs` | `NON_COLOR` 加 `wrap-admin`、`side-w`（**不加就红**，见 §3.3）；新增三条：`layout()` 有那个分支、`.admin-side` 有 CSS 定义、720px 断点里有折行规则 |
| `scripts/e2e-check.mjs` | 新增 §验收表里 1–6 条（复用那一段已有的管理员 / 只读会话） |

**验收断言**（HTTP + 产物层；**每一条先证明前提成立**，沿用既有纪律）：

| # | 前置 | 断言 |
| --- | --- | --- |
| 1 | 管理员已登录 | 逐个 `GET` 六个管理台路由：响应里都有 `.admin-side`，且**恰好一项**带 `aria-current="page"`，它的 `href` **等于当前路径** |
| 2 | 管理员已登录 | 侧栏里六个模块名 + 两个组标签（运维 / 内容）都在；条目**不带计数**（断言里没有数字徽标那种形状） |
| 3 | 只读已登录 | `GET /admin/targets` → `403`，且响应里**没有** `.admin-side`（`#59` §5） |
| 4 | 已登录 | `GET /`、`/status`、`/posts` → 响应里**没有** `.admin-side`（侧栏只在管理台内部） |
| 5 | 管理员已登录 | `GET /admin` → 顶栏「管理」**仍**带 `aria-current="page"`（`#59` §1.1：这条不动） |
| 6 | 管理员已登录 | `GET /admin/articles?edit=<某篇>` → 侧栏仍渲染，且高亮的是**文章**（不是「概览」） |
| 7 | — | `npm run check:style` 全绿（新 token 进了 `NON_COLOR`，六个类名都有定义，`:root` 仍恰好一个、13 色不变） |
| 8 | — | `npm run verify` + `npm run check:e2e` 全绿 |
| 9 | — | **≤720px 折行目视**：headless 截图看一遍（`?` 见下），把看到的结果写进票面 —— 规则可断言，**观感只有眼睛能判** |

> 第 9 条是 map 迷雾里最后一条（「折叠成横向条目条后的可用性：规则可断言，目视未验」）。
> 这张票**负责把它关掉**：截一张窄屏图，贴进票面，说清「挤不挤、组标签碍不碍事」。不许用「规则已加」代替。

**边界（这张票不做）**：粘性侧栏 · 条目计数 / 徽标 · 第二层顶栏 · 403 页的侧栏（`#59` §5 已定不长）·
顶栏 `nav()` 与 `.site-nav` 的任何改动 · 顶栏「管理」的 `aria-current` 语义（`#59` §10）· 主题相关（已落地）。

**交付**：清掉两句**今天就已经是假的话**，把决定书回填成事实，跑一次全量并登记。

| 文件 | 改什么 |
| --- | --- |
| `CONTEXT.md:113` | **管理台** 词条写「`/admin` 及其下的**四个**子页（目标 / 账号 / 备份 / 站点设置）」—— #50 加了文章页之后这句就是假的。改成六个模块 + 侧栏这条导航 |

**验收**：`grep -c "四个子页" CONTEXT.md` → 0；`grep -c "四页<strong>都能写"` → 0（含 e2e）；全量 `verify` + `check:e2e` 绿。

**为什么单独一批（而不是并进票①）**：这两句假话**不依赖侧栏** —— 它们今天就已经错了。
把它塞进一个功能改动里，等于让一个**既存缺陷**搭便车；单独一批的验收是 grep 级的、可以**先做**。
第二批同时是 `#59` 决定书的回填与最终回归记录的家（`#59` 决定书 §7/§8 自己就是这么要求的）。

## 3. 切分时新发现的三件事

### 3.1 标题里的「与主题」已是历史

`#61` 的标题是「落地切分：**侧栏与主题**实现切成哪几批」，但 `#60` 的收口**已经把主题落地了**
（`style.css` 的 `:root` = B 浅 13 值、删掉 `prefers-color-scheme`、断言改写，提交 `4dd5f3a`）。
照旧标题切，会切出一张**空票**。本文件因此只切侧栏；主题的落地证据在
[`docs/theme-decision.md`](theme-decision.md) 与 `#60` 的票面。

### 3.2 两句今天就已经是假的话，且其中一句被 e2e 钉着

- `CONTEXT.md:113`「四个子页」（#50 之前是真的）。
- `src/views.ts:281-282`「四页都能写」+ `scripts/e2e-check.mjs:1025-1028` 断言它（e2e 的断言标题叫
  「概览页明说四页都能写（自述必须是真话）」—— 断言本身没说谎，说谎的是**被断言的文案**）。

侧栏把「文章」摆到明面上之后，这两句会更显眼。它们归票②。

### 3.3 `NON_COLOR` 是票① 的硬地雷

`style-check.mjs` 用「`:root` 里的 token 减去 `NON_COLOR`」来数颜色，并且现在断言**恰好 13 个**。
`--wrap-admin` / `--side-w` 是**非颜色** token：**不同时把它们加进 `NON_COLOR`**，它们会被数成第 14、15 个颜色，
`check:style` 当场红。这不是可选步骤，是票① 的第一件事。

## 4. 全局约束（两张票都适用）

1. **每张票合入后站点必须可用**，且**必须先跑绿再关票**：`npm run verify` + `npm run check:e2e`。
2. **一票一次会话做完**；做不完就如实登记「写到哪、什么没跑」，不拖着关票。
3. **断言必须继续「先证明前提成立」**：第 1 条要先断言「同一响应里有那个侧栏」，否则「恰好一项高亮」在空页面上也恒真；第 3/4 条要先证明前提（是 403 / 是那个页面）。
4. **不放宽既有断言**：`#60` 刚把 token 表收紧成一个 `:root` + 13 色，`#45` 的对比度债不许借回来。
5. **新类名必须同时进 CSS**（`style-check` 的「渲染的类名都有定义」）；**新颜色必须同时进 PAIRS**（若引入任何新的前景/背景对）。
6. **`scripts/` 不进生产镜像**：这两张票都不该新增运行时代码。
7. **目视未验的项必须在票面写清楚** —— 票① 的第 9 条是唯一一条，写完它就关掉了 map 的最后一块迷雾。

## 5. 顺序与「每票可用」的关系

**硬依赖（写进阻塞边）**：② ← ①（回填与最终记录要等侧栏落地）。软件层面 ① 不 depend 任何票。

| 票合入后 | 用户能做什么 |
| --- | --- |
| ① | 在管理台里**一条左侧导航点即达**（本图目的地的达成点）；其余页面一个像素没变 |
| ② | 文档与页面自述不再有假话；全量回归的最终数字有地方可查 |
