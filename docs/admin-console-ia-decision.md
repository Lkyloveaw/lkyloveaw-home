# 管理台的信息架构与入口

本文件是「管理台的信息架构与入口」这张票的产出（map：[个人站自管化](https://github.com/Lkyloveaw/lkyloveaw-home/issues/20)）。

票：<https://github.com/Lkyloveaw/lkyloveaw-home/issues/23>

它把 map 目的地第 ② 条（「一个按角色保护的**管理台**」）落到**看得见的那一层**：
分成几个页面、链接挂在哪、只读用户撞上它会看到什么、写完一条之后屏幕上是好消息还是坏消息、
哪些动作要二次确认。**不管**写路径怎么鉴权（#25 定）、样式 token 长什么样（#21 定）。

> ⚠ **本票只产决定**（map 目的地：本图只产决定）。本文**不含实现代码**。
> 落地由 [实现批次怎么切](https://github.com/Lkyloveaw/lkyloveaw-home/issues/27) 切出的批次票执行。

---

## 0. 五个决定（一句话版）

| 问题 | 结论 |
| --- | --- |
| 分标签还是单页 | **都不是**：一个 `/admin` 概览页（四块摘要卡，不重复数据，给链接）+ **四个子页** `/admin/targets` `/accounts` `/backups` `/settings`，每页一个主题。目标的**分组**用页面内分组标题，**不进 URL** |
| 入口放哪 | **顶栏第 5 项**，标签「管理」，`aria-current="page"`，**只对管理员渲染**；`/status` 面板不加右上角入口，页脚不加 |
| 只读用户看到什么 | 顶栏**不给入口**；直接访问 `/admin` 或任一子页 → **403 页**（**不是** 404）。只读没有「只读视图」，也没有「空壳」 |
| 表单校验与错误呈现 | **失败就地重渲染**（`400` + 显式横幅 + 保留已填输入），**成功 302 回跳**（PRG），提示经一个闭集 `?notice=<key>` 传递。沿用 `notice`，但**新增 `notice-bad` 档**（`#10` 的「失败要显眼」既有取舍） |
| 二次确认 | **JS 弹窗不用**（本仓禁用 JS 也能用）。三类动作加一个**必勾的确认框**（`<input type="checkbox" required>`）：重置口令 · 停用账号 · 降级角色。停用/启用目标**只加一行后果说明**，不设卡 |

## 1. 路由与页面切分

```
GET  /admin                     概览（四块摘要卡 + 链接）
GET  /admin/targets             目标：列表 + 新增 + 改 + 启停
GET  /admin/accounts            账号：列表 + 新增 + 角色 + 启停 + 重置口令
GET  /admin/backups             备份：列表 + 手动触发一次
GET  /admin/settings            站点设置：标题 / 描述 / 探测间隔
```

写操作**一律 POST 到同一路径**（`/admin/targets`、`/admin/accounts` …，用隐藏字段 `action` 区分动作），
不另开 `/admin/xxx/create` 这类动词路径。理由：动作集合是逐个加出来的，
动词路径会让「新增一条目标」和「停用一个目标」长成两条独立路由，而它们共享同一套校验与权限判定；
一个 `action` 字段让**一处守卫**覆盖整页的写操作（`roles-decision.md` §3 的「一个守卫函数」纪律）。

### 1.1 为什么不是「一个页面分区块」，也不是「标签页」

| 方案 | 否掉的理由 |
| --- | --- |
| **一个长页面分四个区块** | 顶栏 4 项 + 四个区块的表单与列表，页长轻松超过 3 屏；`--wrap` 是 900px（`style.css:17`），没有侧栏空间，滚动定位就是唯一导航。而且「提交设置」与「新增目标」共用一个 URL，POST 的 `action` 命名空间会开始互相污染 |
| **标签页** | 标签要么是真链接（那就是分页，只是换了皮），要么是 JS 切换（本仓**禁用 JS 也要能读能写**，`style.css` 与 `status.js` 的既有约束）。**真链接 + 分页**才是这个仓库的形状 |
| **分页 + 概览页** | 每一页都短、都能一次看完；`/admin` 概览页给出「现在是什么状态」，是运维第一眼看的地方；窄屏不需要横向标签条 |

**为什么概览页只放摘要卡、不放数据本身**：概览页重复渲染目标列表，就多了一处会和 `/admin/targets` 不一致的地方
（两个数据源渲染同一份数据 = 两份真相，本仓库反复否掉的东西）。概览页只放**计数与最新时间**：
目标 N 个（启用 M）· 账号 N 个（管理员 M / 停用 K）· 最近备份时间 · 当前站点标题与探测间隔。

**计数一律现算，不落库、不缓存**（`store.ts` 的同一判断：这个数据量下 SQLite 聚合是毫秒级，缓存会引入第二个真相）。
计数与列表在极短窗口内可能相差一两条，可接受——它们是「一眼的状态」，不是账本。

### 1.2 目标的**分组**为什么不进 URL

`targets.json` 的 `group` 是**目标的一个字段**（`config.ts:14`），
面板（`statusPage`）今天就是按它分标题渲染的（`views.ts:333-339`）。
管理台的 targets 页沿用**同一手法**：按 `group` 分标题，每条目标一行。

- 若把分组提升成 URL（`/admin/targets/办公/...`），就凭空造出「分组」这个实体：
  它得能被重命名、能空、能被删除，而现在它只是字符串字段——**引入一个没有需求的实体**。
- 分组名是用户输入，进 URL 就要处理编码与「分组改名后旧书签 404」。
- 顶栏已经 5 项；分组再进导航就是二级导航，900px 宽度下会开始换行。

分组要能改，改的是**目标行的 `group` 字段**（编辑表单里的一个文本框），改完分组标题自然跟着变。

## 2. 入口：顶栏第 5 项，只对管理员渲染

`nav()` 今天把 4 项写死在函数里（`views.ts:58-71`），`LayoutOptions['active']` 是一个**四值联合**。
本票的决定：

```ts
active: 'home' | 'posts' | 'status' | 'about' | 'admin'
```

- **管理员**：顶栏多一项 `<a href="/admin">管理</a>`。
- **只读用户**：这一项**不渲染**（而不是渲染成灰色或跳到 403——那等于每次点都吃一次错）。

**为什么是顶栏，不是面板右上角、也不是页脚**：

| 位置 | 否掉的理由 |
| --- | --- |
| `/status` 面板右上角 | 管理台**不只服务面板**：账号、备份、站点设置与面板无关。挂在面板上等于宣布「管理台是面板的附属」，而它其实与 `首页/分享/系统可用性/关于` 平级 |
| 页脚 | 页脚今天是**站点描述**一行（`views.ts:92-96`），把功能入口塞进版权区，等于告诉用户「这不是正经入口」。而且页脚在每个页面底部，`/status` 的长页面要点到最底才看得见 |
| 顶栏第 5 项 | 与既有 4 项同一层级、同一渲染路径、每页都在同一个位置。**5 项在 900px 与窄屏下都不换行**（`style.css:98` 有 `flex-wrap`，每项 `5px 10px` 内边距，中文两项标签最宽合计约 300px） |

**`active: 'admin'` 在四个子页上都要置位**（点进 `/admin/accounts`，顶栏「管理」仍要高亮）——
子页之间靠**页面内的返回链接**导航，不引入第二层顶栏。

**登录页不加**：`loginPage()` 刻意不用 `layout()`（`views.ts:110-113`），这个决定不动。

## 3. 只读用户撞上管理台：顶栏不给入口 + `403`

`roles-decision.md` §1 已定两件事：**只读进不了管理台（整块不可用）**，
以及**第一版不做只读视图**；本票要定的只是**呈现形态**，它留给本票的就是这一格。

| 访问方式 | 结果 |
| --- | --- |
| 顶栏 | **不渲染**「管理」这一项（§2） |
| `GET /admin`（只读，已登录） | **403**，站内 `layout()` 渲染的中文页：「这个页面需要管理员权限。当前账号是只读。」+ 回首页链接 |
| `GET /admin/<任一子页>`（只读） | 同上 403 |
| `POST /admin/<任一子页>`（只读） | **403**，不写、不重定向（写接口的状态码归 #25 定，本票只定「不是 302」） |
| 未登录访问 `/admin*` | 由既有闸门处理：302 → `/login?next=/admin`（`docs/login-gate-decision-table.md` §3 原样） |

### 3.1 为什么是 403 而不是 404

- **404 的隐藏是假的**。这个仓库的既有判断是「真实攻击者最多是已登录的用户」
  （`docs/api-status-fields-decision.md` 的立场）：只读用户只要数一下顶栏项数、
  或者问一句同事，就知道管理台存在。用 404 换来的只是**运维自己排查时的一次困惑**。
- **403 是一次信息量正好的回答**：它告诉能看懂的人「你权限不够」（而不是「你地址敲错了」），
  这正是故障排查需要的信号。本仓库的既有取舍是「**失败要显眼不要静默降级**」，
  把「权限不够」伪装成「不存在」正是一种静默。
- **403 页要说清自己是谁**：中文一句话 + 当前角色，不做成裸状态码。

### 3.2 为什么不是「只读视图」或「空壳」

`roles-decision.md` §1 已明确「不做只读视图」，本票沿用并补上理由：
只读视图（能看不能改）会立刻长出一串新问题（哪个按钮灰、灰的按钮点了说什么、
列表里要不要显示 URL 与错误详情），而**第一版没有「只读用户也要排障」的真实需求**。
**空壳**（渲染带禁用控件的表单）比 403 更差：它把「你没有这个能力」表达成「你能，只是现在不行」，
是误导；而且禁用控件在 HTML 层只是 `disabled`，**服务端仍然必须再判一次**——
那这一层壳除了骗人没有任何作用。

## 4. 表单校验与错误呈现

### 4.1 成功：302 回跳 + `?notice=<key>`（PRG）

写成功 → `302` 回本页 → 页面顶部一条 `notice`。**为什么必须回跳而不是就地 200**：
刷新会重复提交（浏览器的「确认重新提交」弹窗是用户体验最差的一种破坏性提示），
而回跳之后按 F5 只会重新 GET 一次，无害。

**提示文本走一个闭集 key，不是自由文本**：`?notice=target-disabled`，
文本表住 `views.ts`（`NOTICE_TEXT: Record<string, string>`）。
未知 key → **不显示任何提示**（不渲染 `?notice=<攻击者编的字符串>`）。

> 为什么不做「自由文本 + 转义」：转义能挡住 XSS，但挡不住**社工**——
> 一条 URL 能让页面显示任意「已停用账号 alice」的字样，而这个页面的可信度来自「它说的就是真的」。
> 闭集把这条路堵死，代价只是新增动作时多写一行文本。

| 动作 | notice key |
| --- | --- |
| 新增 / 修改目标 | `target-saved` |
| 停用 / 启用目标 | `target-enabled` / `target-disabled` |
| 新增账号 | `account-created` |
| 改角色 | `role-changed` |
| 停用 / 启用账号 | `account-disabled` / `account-enabled` |
| 重置口令 | `password-reset` |
| 触发备份 | `backup-started` |
| 保存设置 | `settings-saved` |

### 4.2 失败：`400` + 就地重渲染 + 保留输入

| 类别 | 状态码 | 呈现 |
| --- | --- | --- |
| **校验失败**（缺字段、URL 不合规、口令太短、两次不一致、id 重复、确认框没勾） | **400** | 同页重渲染：顶部 `notice-bad` 横幅写明**哪一条**错了；**表单保留刚填的值** |
| **动作被守卫拒绝**（最后管理员、改自己的角色） | **400** | 同上，文案说明为什么（「这是最后一个启用中的管理员」） |
| **权限不足**（只读访问） | **403** | 403 页（§3） |
| **服务端异常**（DB 写失败） | **500** | 显眼横幅 + `console.error`；**不吞掉**、不假装成功 |

**为什么失败不用 PRG**：PRG 解决的是「刷新重复提交」，而校验失败**没有提交成功**，
把用户填的东西丢掉再让他重填一遍是最没必要的惩罚。
**密码字段例外**：重渲染时**不回填**口令（`type="password"` 也不回填），只保留其他字段。

**为什么 `400` 而不是 `200`**：`200` 会让「写失败」在日志、`curl -i`、
以及任何自动化里看起来像成功。这与「失败要显眼」同一条判据。

### 4.3 `notice` 需要新增一档样式

今天只有一种 `notice`（`style.css:336-341`，蓝左边框）与 `status-banner`（黄，用于面板的自动刷新失败）。
本票定：

| class | 用途 |
| --- | --- |
| `.notice` | 成功/中性（沿用） |
| `.notice-bad` | **新增**：校验失败与守卫拒绝，左边框用 `--bad`，文字用 `--bad` |
| `.notice-warn` | **新增**：不致命但要知道（如「今天已备份过，本次跳过」），左边框 `--warn` |

`status-banner` 保留原样（它是 JS 在面板里注入的，与管理台无关）。

### 4.4 提交的是哪个动作：隐藏字段 `action`

每个表单带 `<input type="hidden" name="action" value="target-disable">`。
服务端把 `action` 当一个**闭集**枚举（未知值 → 400），不是自由字符串。
为什么不用「每个动作一条 URL」：见 §1；为什么不用多个 `<button name="action" value="...">`：
一个表单里放多个提交按钮时，**表单里其他的字段仍会一起提交**，
「停用」按钮旁边就摆着可编辑的 URL 输入框，误点时会连编辑一起提交。分开一个个表单更安全。

## 5. 破坏性操作的二次确认

**先立判据**（不然「要不要确认」会变成逐个拍脑袋）：

> **要二次确认的，是「点了之后，屏幕外的某个人会立刻受影响」或「踩了之后要靠另一条通道才能恢复」的动作。**

按这条判据过一遍：

| 动作 | 屏幕外有人受影响？ | 恢复容易？ | 结论 |
| --- | --- | --- | --- |
| 停用 / 启用**目标** | 否（只影响本站的探测与本页显示） | 是（再点一次，历史全在） | **不设卡**，只加一行后果说明 |
| 修改目标（改名/URL/分组） | 否 | 是 | 不设卡 |
| 新增账号 | 否（新号默认只读） | 是 | 不设卡 |
| **重置口令** | **是**（该账号全部设备立刻掉线） | 否（口令只有操作者知道，要另行告知） | **必勾确认框** |
| **停用账号** | **是**（该账号全部设备进不来） | 是（再启用即可） | **必勾确认框** |
| 启用账号 / 改角色为 admin | 否 | 是 | 不设卡（守卫另有规则） |
| **降级角色**（admin→readonly） | **是**（对方下次请求就失去管理台） | 是（能再提权） | **必勾确认框** |
| 触发备份 | 否 | 是（产物是新增文件） | 不设卡 |

### 5.1 用必勾的复选框，不用 JS `confirm()`

```html
<label class="confirm">
  <input type="checkbox" name="confirm" required>
  我确认：这会立刻让「alice」所有设备上的登录失效。
</label>
```

- **`required` 复选框是 HTML 原生能力**，不需要一行 JS。本仓的既有约束是
  **禁用 JS 也要能读能写**（`style.css` 的 `prefers-color-scheme`、面板的内联 SVG 都是这个取向），
  `confirm()` 在禁用 JS 时**完全不执行**——那三次点击就能造成的破坏就少了一道唯一防线。
- **确认框要写清后果**，不是「确定吗？」：「这会立刻让 alice 所有设备上的登录失效」
  比「确定要重置口令吗」多给出的是**唯一有用的那条信息**。
- 服务端**必须独立校验** `confirm` 字段（缺失或非勾选 → 400）。
  这是「点错了」的减速带，**不是**权限控制，所以它不替代任何守卫。
- ⚠ **与既有行为的一处对齐**：`/password`（改**自己**的口令）今天**没有**确认框
  （`views.ts:402-424` 的状态页上只有表单）。本票**不改它**：
  改自己的口令不满足判据（受影响的是操作者本人，且他知道自己在做什么）。

### 5.2 停用/启用目标为什么不设卡

「停用目标」看起来像破坏性动作，但**判据说不**：它不踢任何人、不删任何数据（历史保留，`map Notes` 第 3 条），
再点一次就回来了。给它加确认框的代价是**每天都要多点一次**，换来的是防一个点错就能修好的操作。
正确的做法是**在按钮旁写清后果**：「停用后不再探测，历史保留；面板上显示为已停用」。
真正需要确认的是「停用**账号**」——那个会把人挡在门外。

## 6. 页面规格

每页都是服务端渲染的 `layout()` 页面，`active: 'admin'`，**不挂 `status.js`**（管理台的数据是自己刚写的，不需要 30 秒轮询；
`/admin/targets` 上的启停是写操作，与自动刷新的语义冲突）。

### 6.1 `/admin`（概览）

四块摘要卡（复用 `.stat-strip` / `.stat` 的既有样式），每块卡右下角一个链接进子页：

| 卡片 | 内容 |
| --- | --- |
| 目标 | `启用 N / 共 M`（分组数 G） |
| 账号 | `共 N`（管理员 M · 停用 K） |
| 备份 | 最近一次产物的时间与文件名；今天是否已备份 |
| 站点设置 | 当前标题、描述、探测间隔 |

**零管理员告警**落在这里：`roles-decision.md` §5 要求「启动时检出 → 告警」，
概览页是它**唯一合适的常驻位置**（启动日志只在重启时看得到）：
一条 `notice-warn` +「用 `node dist/cli/passwd.js --user X --role admin` 修复」。
这条要**每次渲染都算**（`SELECT COUNT(*) FROM users WHERE role='admin' AND enabled=1`），
不靠启动时算好的一次性状态。

### 6.2 `/admin/targets`

按 `group` 分标题（与 `statusPage` 同一手法），每条目标一行：状态点 · 名称 · URL · 分组 · 启用状态 · 操作。

| 动作 | 表单形态 |
| --- | --- |
| 新增目标 | 页面顶部一个折叠/展开都可的表单：`id` · `name` · `url` · `group` · `expectStatus` · `timeoutMs` · `enabled` |
| 编辑 | 行内表单（同一行的字段直接是可编辑的 input），一个「保存」 |
| 停用 / 启用 | 行内一个按钮（无确认框，§5.2），旁边一行后果说明 |

- **`id` 在编辑表单里只读**：`id` 是历史库主键，改 id 等于丢掉该目标的全部历史
  （`CONTEXT.md` 的**目标**词条、`config.ts:8`）。UI 上不给改的机会，
  比「允许改但弹警告」更简单也更安全；真需要改 id 就是「新建一个 + 停用旧的」。
  （#26 要定的是目标真源与首次导入，**本票只定 UI 上的这一个约束**。）
- **校验必须复用既有函数**，不重写一套：`config.ts:108` 的 `validateTargetUrl()`
  与 `config.ts:125` 的 `normalizeTargets()`（协议白名单、URL 凭证拦截、重复 id）。
  重写一份会让「文件里被拒的 URL 在网页上能存进去」。
- 页面顶部要有一条「真源已迁到数据库」的说明，并把 `aboutPage()` 里
  「编辑 `targets.json`」的旧文案**标成待改**（§8）。

### 6.3 `/admin/accounts`

| 列 | 内容 |
| --- | --- |
| 用户名 · id | `id` 只读展示 |
| 角色 | admin / readonly，可改**别人**的 |
| 状态 | 启用 / 已停用 |
| 凭据代次 | `token_version`（排查「为什么掉线」时唯一有用的数字） |
| 操作 | 改角色 · 停用/启用 · 重置口令 |

- **不能改自己的角色、不能停用自己**（`roles-decision.md` §4）：这两行对**当前登录者自己**不渲染操作按钮，
  服务端同样拒绝（双保险，与 §3.2 同理：UI 不渲染不等于服务端可以不判）。
- **重置口令必须就地输入新口令**（不生成随机口令）：生成随机口令就得有地方展示它，
  展示完还得让操作者抄下来，等于把口令塞进页面与日志。表单两个字段：新口令 + 确认，
  加一个必勾的确认框（§5）。
- **最后管理员守卫的拒绝要显示在页面上**（400 + `notice-bad`），
  文案要说清是哪一条规则（「这是最后一个启用中的管理员，不能再降级/停用」）。
- 角色列用**领域词**渲染（管理员 / 只读），不显示 `admin` / `readonly` 原始值
  （`CONTEXT.md` 的**角色**词条就是这两个中文词）。

### 6.4 `/admin/backups`

- 列出 `config.backupDir` 下的产物：文件名 · 大小 · 时间（按时间倒序）。
- 一个「立即备份一次」按钮（`action=backup-now`），**无确认框**（§5 判据：产物是新增文件，不覆盖任何东西）。
- 列表为空与目录不可读**要分开显示**：前者是「还没备份过」，后者是**故障**（`notice-bad` + 错误原因）。
  混成同一句「暂无备份」就是一次静默降级。
- **不做「下载产物」**：备份产物是整库，含 `password_hash` 与全部历史，
  一次点击就能把它拉到一个可能不带 HTTPS 的浏览器里；且 `db.backup()` 已经写在同一个 volume 上，
  运维需要时走文件系统。要下载就得先有 HTTPS 与访问控制，属 map 迷雾（HTTPS）与后续需求。
  （`map Notes` 第 4 条只承诺「列表 / 手动触发一次」。）

### 6.5 `/admin/settings`

- 标题 · 描述 · 探测间隔（秒）三个字段 + 保存。
- **`.env` 与 DB 谁优先、首次值怎么迁移归 [#22](https://github.com/Lkyloveaw/lkyloveaw-home/issues/22)**，
  本票只定页面上**呈现哪些字段**（就是 map Notes 第 4 条那三个）与「保存后当前页立刻显示新值」。
- 改探测间隔是否立刻生效（定时器已启动）也归 #22；本票只要求**保存成功后页面上读到的就是新值**，
  不承诺「探测轮次已经切换到新间隔」。

### 6.6 管理台里的破坏性提示要「说后果」，不是「说动作」

文案的统一判据，交给批次票的验收用：

| 差 | 好 |
| --- | --- |
| 「确定要停用吗？」 | 「停用后不再探测；历史保留，面板上显示为已停用。」 |
| 「确认重置口令」 | 「这会立刻让 alice 所有设备上的登录失效；口令由你告知对方。」 |
| 「确认降级」 | 「降级后对方下一个请求就进不了管理台（不会踢掉他的登录）。」 |

第三条的括注是 `roles-decision.md` §3 的结论（角色变更不踢会话），
写成提示能省掉一次「为什么他还能看面板」的追问。

## 8. 连带影响（落地时必须一起改，否则验收是假的）

1. **`aboutPage()` 的旧文案会变成错的**：它今天写着「编辑 `targets.json`，加一条记录」
   （`views.ts:301-308`）。目标真源搬进 DB 之后，这句话是**假指示**。
   必须改成「在管理台 → 目标里新增」（`targets.json` 只在首次导入，`map Notes` 第 3 条）。
   落点写在这里，改归批次票。
2. **登录页的 `noAccounts` 提示仍然成立**（零账号时环境变量建号），不受本票影响。
3. **`/admin` 不需要进 `PUBLIC_PATHS`**，也不需要进 `KNOWN_PAGES`：
   `isKnownPath()` 只服务登录回跳的落点校验（`auth.ts:34-47`），
   未登录访问 `/admin` 会 302 到 `/login?next=/admin`，登录后回到 `/admin`，
   而 `next` 的校验发生在**登录页渲染时**——`/admin` 不在 `KNOWN_PAGES` 里会被丢弃、回退到 `/`。
   **这是一个真实的小退化**（管理员被弹到首页而不是他要去的地方）。
   处理：把 `/admin` 与四个子页加进 `KNOWN_PAGES`（它们只对管理员有效，
   只读用户回跳到 `/admin` 会看到 403 页——那是**正确**的回答，不是缺陷）。
4. **计数查询会碰到 `config.targets` 之外的真相**：管理台必须显示**库里**的目标
   （`map Notes`：SQLite 是唯一真源）。而首页/面板今天读的是启动时冻结的 `config.targets`
   （`config.ts:177`）。**两条真相会短暂并存**，直到 #26 把探测与视图改成读 DB。
   本票的取向：**管理台只读库**，不复用 `buildSummary()`，并在页面上不承诺「面板也已同步」。

## 9. 验收（决策票：可断言的事实）

落地时的断言清单（HTTP 层，落 `scripts/e2e-check.mjs`）：

| # | 前置 | 操作 | 预期 |
| --- | --- | --- | --- |
| 1 | 管理员已登录 | `GET /` | 顶栏含「管理」链接 |
| 2 | **只读**已登录 | `GET /` | 顶栏**不含**「管理」链接（且这条要先断言同一响应里有另外 4 项导航） |
| 3 | 管理员已登录 | 逐个 `GET /admin`、`/admin/targets`、`/admin/accounts`、`/admin/backups`、`/admin/settings` | 全部 `200`，且顶栏「管理」带 `aria-current="page"` |
| 4 | 只读已登录 | 逐个 `GET` 上面 5 条 | 全部 `403`，响应是站内页面且含「需要管理员权限」 |
| 5 | 未登录 | `GET /admin/accounts` | `302` → `/login?next=/admin/accounts`；**带该 `next` 登录后落回该页**（回归 §8.3） |
| 6 | 管理员 | `POST /admin/targets` 带一个未勾 `confirm` 的动作 | `400`，且**没有**发生写操作（先断言该状态未变） |
| 7 | 管理员 | `POST /admin/accounts` 提交「最后管理员降级」 | `400` + 页面含守卫文案，且**该账号仍是 admin** |
| 8 | 管理员 | `POST /admin/accounts` 提交「停用自己」 | `400`，且自己仍是启用状态 |
| 9 | 管理员 | 正常 `POST` 一次（如新增目标） | `302` 回本页；**再 GET 一次**能看到目标在列表里与 success notice（防「302 但没写进去」） |
| 10 | 任意 | `GET /admin?notice=随便编的字符串` | 页面里**不出现**该字符串（闭集生效） |
| 11 | 管理员 | 提交一个非法 URL 的新目标 | `400`，页面**保留**已填的其它字段 |

**断言质量要求**（沿用既有原则）：每条**必须先证明前提成立**——
第 2 条必须先证明同一响应里有 4 项导航（否则「不含管理链接」在一个空页面上恒真）；
第 7/8 条必须先断言操作前该账号确实是 admin/启用（否则恒真）；
第 9 条必须**写后读**（只看 302 会被「302 了但没写」骗过，这正是 `docs/session-decision.md` §12 的同类要求）。

**已在本机跑过的验证**：**没有**。本票产出时的会话里 `ops_bash`
（缺 bash IPC 兼容收据）与 `pwsh`（执行策略禁止 `prepare-workspace.ps1`）都不可用，
所以上面 11 条**一条都没跑**。它们与 `docs/session-revoke-decision.md` §11 同一种性质：
**待验证的断言清单，不是已验证的结论**。落地时跑出与本文不一致的，**改本文**。

## 11. 边界

- **不定**写路径的鉴权判定函数与 CSRF（[写路径的鉴权面](https://github.com/Lkyloveaw/lkyloveaw-home/issues/25)）。
  本票假定的接口是「`decideRequest` 能交出当前用户与角色」——**形状由 #25 定**。
- **不定**视觉 token（字体栈、字号阶梯、色板；[整站视觉原型](https://github.com/Lkyloveaw/lkyloveaw-home/issues/21)）。
  本票只声明管理台**属于「数据面」**（map Notes 第 6 条：面板 / 管理台 / 登录走终端等宽化），
  以及复用哪些既有 class。
- **不定**目标真源、首次导入与探测热加载（[目标网页化的落地设计](https://github.com/Lkyloveaw/lkyloveaw-home/issues/26)）；
  本票只定「管理台读库」与「编辑表单里 `id` 只读」。
- **不定** `.env` 与 DB 的优先级、探测间隔是否立刻生效（[站点设置与备份的真源边界](https://github.com/Lkyloveaw/lkyloveaw-home/issues/22)）。
- **不做**：会话管理 UI（看设备、踢单台），`map Notes` 第 4 条与
  `docs/session-revoke-decision.md` §8 都已排除。
- **不做**：备份产物下载（§6.4 给了理由：整库含口令哈希，且站点还是 HTTP）。
- **仍是迷雾**：管理台的**审计**（谁在什么时候改了什么）——
  本票让它成为一件真会发生的事（有五个页面可以改），但「在哪看、留多久」仍不够锐利，不升票。
- 本票产出决定与落点，**不写实现代码**。
