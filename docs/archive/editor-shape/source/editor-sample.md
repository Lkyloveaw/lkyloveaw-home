面板上一开始只有「可用 / 不可用」两个状态，用了一阵发现不够用：某个系统一直是绿的，但同事们都在抱怨慢。于是补了指标。

## 三个指标，各回答一个问题

| 指标 | 回答的问题 | 什么时候会暴露问题 |
| --- | --- | --- |
| 可用率 | 它坏过吗 | 有明确的宕机窗口 |
| 平均 / P95 延迟 | 它好用时好用吗 | 系统活着，但慢到影响使用 |
| 连续可用时长 | 它稳定多久了 | 反复闪断，可用率看着还行 |

单独看可用率最容易骗人：一个每天重启两次、每次只断 30 秒的系统，可用率能到 99.9%，但用户实际体验是「这东西老抽风」。

## 为什么用 P95 而不是只看平均

平均延迟对少数极端值不敏感。10 次请求里 9 次 50ms、1 次 5 秒，平均只有 545ms，看起来还能接受；但 P95 会诚实地告诉你 5 秒。

> 如果只能留一个延迟指标，留 P95。

## 状态不能只有两档

实际跑下来有三种情况必须区分开：

- **可用**：状态码在预期范围内；
- **异常**：能连上，但状态码不对（比如返回 503、或者跳到了登录页）；
- **故障**：连不上、超时、DNS 解析失败。

「异常」这一档特别有用——它往往意味着依赖的数据库或者缓存挂了，而反向代理还活着。这时候系统严格来说是「能访问的」，但用户什么都干不了。

```json
{
  "id": "portal",
  "name": "统一门户",
  "url": "http://10.0.0.10/",
  "expectStatus": [200, 302]
}
```

`expectStatus` 显式列出哪些状态码算正常。默认是 200–399，但有些系统正常就会返回 302 跳转，这类情况必须能配置。

## 别把探测做成压力测试

轮询间隔我定在 60 秒，超时 5 秒。对几十个内网系统来说这个量级完全可以忽略，而且探测请求走的是 GET 一个静态入口页，不会碰到需要鉴权的接口。

如果某个系统特别脆弱，就在它的配置里单独把间隔调大，而不是全局调慢——一个系统的问题不该拖累其他系统的观测粒度。

## 原型加料 ①：中文长段落（不是原文）

这一节是原型加料，用途只有一个：把「一篇要滚好几屏的中文长文」这个手感摆出来。真实文章多数在两千字上下，编辑区长文本时最容易被忽略的三件事是光标位置、滚动位置和段落感——光标在哪，决定你改一句话要不要先找半分钟；滚动位置在哪，决定你「回去看一眼上文」的代价；段落感则决定你在纯文本与渲染结果之间的落差有多大。三件事在短样本上都看不出来，只有把正文拉长到需要滚动才会现形。

另一件只有长文才暴露的事是「预览跟着谁走」。写一段、看一段的节奏在短文里几乎无感，到了长文里就变成一次持续的判断：预览是不是停在我正在写的地方？如果预览总是从开头渲染，我每改一段就得在预览里重新找一次位置；如果预览只更新到我的光标处，那上面的段落我其实没在核对。这个取舍在三个变体里的答案完全不同，也正是这次要你亲手比出来的东西。

中文还额外压了一层：同样信息量下，中文的字数比英文少、行数却更密，一段两百字的正文在 900px 宽的版心里大约占三到四行。这意味着「一屏能看多少个自然段」比英文版要高，也意味着滚动条的刻度更粗——你一次滚轮下去，可能已经跳过了两个段落。表格与代码块在中文长文里同样是密度异常的地方：它们比正文更宽、更难换行，一旦窄栏里放不下，横向滚动就成了唯一出路。

还有一件与手感无关、但与代价有关的事：长文会放大每一次往返的成本。短文里一次整页刷新只是「顿一下」，长文里同样的刷新要让浏览器重新排一遍两千字的版，而且回来时光标与滚动位置都不在原处。所以「纯文本域 + 服务端预览」这一版在短文上完全够用，在长文上是否还够用，得你自己滚一遍才知道——这也是我把它放在样本里、而不是写在结论里的原因。

## 原型加料 ②：一张真图片（不是原文）

![可用率曲线（样本图，不是真实数据）](/prototype/assets/sample-chart.svg)

上面这张图是原型样本图（`src/prototype/assets/sample-chart.svg`），不是这篇文章的一部分。它的作用是让「图片」这一格有东西可看：站内图片现在**没有任何约定**——`content/` 下两篇真实文章里一个图片引用都没有，渲染层也没有图片目录、没有路径重写、没有上传落点。所以这篇样本里的写法（一个根相对路径 `/prototype/assets/sample-chart.svg`）只是原型的临时做法，真实落点归属另一张票。

图片在编辑器形态里的分歧点很具体：一版是「你会写一段图片语法」，另一版是「你按一个按钮、选一个文件」。前者的代价是路径要你自己记得住，后者要付的是上传接口、存储位置、以及富文本把图片塞进 HTML 之后还能不能原样存回 Markdown。这一格在三个变体里的手感差别最大，请一定滚到这里各试一次。

图片之后再补一段正文，让样本在最底部也保持「有下文」的状态——真实文章很少以一张图结尾。
