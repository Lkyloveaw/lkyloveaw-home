## 1. 五个决定（一句话版）

| 问题 | 结论 |
| --- | --- |
| **落点** | **建在管理台外壳里**：文章写路由 = 管理台的**第 5 个模块** `/admin/articles`，共用 `layout()`、顶栏「管理」、`requireAdmin`、L2 origin 校验、L3 token、PRG `302 + ?notice=<key>`、失败就地重渲染 |
| **判定表边界** | **机制归 #25，对象规则归本模块**：判定顺序、状态码形状、token 形态、幂等判据全在 #25；文章只往那张表**加行**（资格 = 管理员，对象规则 = §7）。文章侧**不许**自己再判一次资格或来源 |
| **接口形状** | **SSR 表单 POST 到同一路径** + hidden `action` 闭集（#23 §1/§4.4 的手法）；**不做 fetch / JSON 写接口**、**不做自动保存** |
| **失败呈现** | 全部沿用 #23 §4.2 / #25 §5.4；文章只有三处增量：**正文必须回填** · 超长正文判 **400**（不是裸 413）· `?edit=` 失效回落列表 + `notice-warn` |

## 2. 为什么是「外壳里」，不是独立路由

### 2.1 结论

文章写路径**不是**第二个后台。它就是管理台的一个模块，与目标 / 账号 / 备份 / 站点设置同一层级：
同一条顶栏入口（#23 §2 的「管理」）、同一套资格判定、同一套失败呈现、同一处 CSRF token 注入。
map Notes 第 2 条已经替这条决定定过性：「两图共用地基：管理台外壳、角色、会话吊销都属那张图」——
本票只是把「文章也用这块地基」明确下来，并划出边界。

### 2.2 独立路由要自己再付一次的三笔账

| 账 | 独立路由下会变成什么 |
| --- | --- |
| **资格判定** | #25 §5.1 的「**一个守卫**」退化成「每套路由各自记得调用」。而「记得」不是机制——漏一次就是一条没有资格判定的写路由 |
| **CSRF token 注入** | L2 是全局钩子（跟着走），但 L3 的 token 注入走 `AsyncLocalStorage` + `csrfField()`（#25 §4.3），**只覆盖 `layout()` 渲染出来的表单**。独立路由若自带页面，就要自己再接一次 ALS 与 `preValidation`：漏一处 = 一个没有 token 的表单，**只有提交时才发现**（403） |
| **失败呈现** | 第二套 `NOTICE_TEXT` 命名空间、第二个 403 页面、第二种「校验失败长什么样」。#23 §1 否掉「标签页」时的原话是同一句判据：**两个地方渲染同一件事 = 两份真相** |
| **入口** | 顶栏只有 5 项（#23 §2 算过 900px 的排版预算）。独立路由要么挤成第 6 项，要么藏成「只有知道 URL 的人能用」的页面——后者是一次**静默入口**，与「失败要显眼」同源地不该做 |

### 2.3 顺带否掉的两个形状

- **`/posts/:slug/edit`（把写动作挂进读面路径）**：`/posts/:slug` 是**公开契约**那把键
  （研究 §5.1 第 1 条：e2e 硬编码、老分享链接），读写共用一条路径会让读的 URL 空间与写的 URL 空间缠在一起。
  而且 `req.params.slug` 今天**不解码**（研究 §2.2），新增一条 slug-in-path 的写路由等于把那条不对称复制到第二处。
- **文章侧自带一套轻鉴权**（例如只验登录、不验角色）：#24 已定「只读不做任何写」，
  自带一套 = 两份判定表；而两份判定表迟早给出两个答案。

## 3. 落点：路由、页面、动作

### 3.1 两条 URL

```
GET  /admin/articles                列表（标题 · slug · 日期 · 状态 · 标签 · 操作）+ 新建表单
GET  /admin/articles?edit=<slug>    同上，并展开该篇的编辑面（正文 textarea + 元数据）
POST /admin/articles                全部写动作（hidden `action` 闭集 + hidden `slug`）
```

**为什么 GET 与 POST 同路径**：沿用 #23 §1 的手法——写操作**一律 POST 到同一路径**，用隐藏字段
`action` 区分动作，不另开 `/admin/articles/create` 这类动词路径。一个 `action` 闭集让**一处守卫**覆盖整页写操作。

### 3.2 动作闭集

| action | 语义 | 语义归谁 |
| --- | --- | --- |
| `article-create` | 新建一篇（**默认草稿**） | 动作存在性 = 本票；slug 怎么来 = #32。「默认草稿」是沿用 map 目的地写的「草稿 → 发布」，不是本票新立的：若 #32 反过来定「新建即发布」，改这一格 |
| `article-save` | 保存标题 / 日期 / 标签 / 摘要 / 正文，**不改发布状态** | 本票 |
| `article-publish` | 草稿 → 发布 | 动作存在性 = 本票；「发布是否立即生效」= #32 |
| `article-unpublish` | 发布 → 退回草稿 | 同上（若 #32 判「发布不可逆」，从闭集删掉这一行） |
| ~~`article-delete`~~ → **`article-trash`** | 移进回收站（软删：只置 `deleted_at`，**不删任何行**） | #32 决定 10 / 15 |
| `article-restore` | 从回收站还原：清 `deleted_at`，**自动回到删除前那个状态**（草稿仍是草稿、已发布仍是已发布） | #32 决定 15 / 18 —— 正交的 `deleted_at` 才做得到，**不需要** WordPress 那种 `_wp_trash_meta_status` 旁路 |
| `article-purge` | **彻底删除**：删文章行 + 它的**全部修订行**，且**必勾确认** | #32 决定 10 / 17 —— 这才是「删稿」原本说的那个硬删 |

**未知 `action` → 400**（#23 §4.4 的闭集纪律：`action` 是枚举，不是自由字符串，更不许拼进文件名或 SQL）。
闭集的成员**已由 #32 定稿**（2026-10-17：原先那个 `article-delete` 拆成 trash / restore / purge 三个）；删/留都是改一行枚举的事，但**闭集本身**是接口形状的一部分，不留给实现随手加。

### 3.3 编辑面用的键：公开契约那把（slug），走 `?edit=`

| 理由 | 说明 |
| --- | --- |
| **键要与公开契约同一把** | 读面的键就是 slug（`/posts/:slug`，`src/content.ts:134`）。编辑面再用内部存储键（文件名 / 行号 / 库 id）就等于给同一篇东西配两把钥匙——#26 对目标 id 立过同一条纪律（能改的东西不做历史键） |
| **不复制解码不对称** | 研究 §2.2：`/tags/:tag` 解码、`/posts/:slug` 不解码。往 path 里再加一段 slug 就是把那条坑复制到第三条路由；查询串由 Fastify 统一解码，没有这个分叉 |
| **键失效的姿势温和** | `?edit=` 指向一篇已不在的文章（被删 / 改了 slug）→ 回到列表 + `notice-warn`；而一条 `/admin/articles/<slug>` 路由的键失效就是 404 页（用户看到一个「页面不存在」，不知道是文章没了还是地址敲错了） |
| **⚠ 新增一种「存在但不可编辑」（2026-10-17，#32 加回收站后）** | 回收站里的文章**仍然占着它的 slug**（与 WordPress 一致：它的唯一性检查也不看状态），所以 `?edit=<回收站里的 slug>` **既不是 404、也不打开编辑面**：回到列表 + 提示「它在回收站里，要先还原」。这需要往 `notice` **闭集**加一个键（如 `article-trashed`）——闭集是刻意的（挡社工），所以**新增键本身是一次决定**，不留给实现随手加 |

**代价写在明面上**：编辑面不能单独收藏成一条稳定 URL（草稿改名后书签回落列表）。
可接受：草稿本来就没有对外身份，而**已发布**文章的 slug 稳不稳定归 #32（§7.1 的最后一条）。

### 3.4 页面构成

- **列表**（每行）：标题 · slug · 日期 · 状态（草稿 / 已发布）· 标签 · 操作。
  操作列 = 「编辑」（`?edit=<slug>` 链接）+ 状态切换（发布 / 退回草稿）+ 删除。
  **一个动作一个表单**（#23 §4.4：多按钮共用一个表单会连旁边编辑框一起提交）。
- **新建表单**（页面顶部）：`title` · `slug`（可留空）· `date`（`<input type="date">`，留空 = 当天）·
  `tags`（逗号分隔，服务端走 `toTags` 归一，`src/content.ts:57`）· `summary`（留空 = 读侧派生）· 正文 `textarea`。
- **字段集 = front-matter 的 6 个键，一个不多一个不少**（`title` / `date` / `summary` / `tags` / `draft` / `slug`）。
  研究 §1.1：`parseFile()` 丢弃未知键 → 表单上多出一个字段就是**骗用户**（填了不会被保存）。
  `html` / `readingMinutes` 是派生字段（研究 §1.2），**不进表单**。
- **已发布的行给一个「查看文章」链接**（指向 `/posts/<slug>`，只是链接，不加功能）；草稿**不给**——它直链 404（研究 §5.1 第 4 条），给链接等于给一个必然失败的按钮。
- **列表不分页**，沿用读面（研究 §2.3：全仓无分页实现）：文章数量在个人站量级，一页几行比新加一个 `?page=` 的边界条件更简单；真到上千篇时再开一次决定。

### 3.5 入口与权限

- **入口**：`/admin` 概览页新增**第 5 张摘要卡**「文章」（共 N 篇 · 草稿 M），链接进 `/admin/articles`。
  顶栏**仍然只有一项**「管理」（#23 §2），本模块**不新增**顶栏项——5 项是排版预算，不是随手能加的数。
- **权限：管理员专属**。沿用 #24 对两个角色的定义（`CONTEXT.md` 的**管理员** / **只读**词条）：
  文章写作是一次写操作 ⇒ 只读用户顶栏看不到入口、直访 `/admin/articles` 得 **403**（不是 404，
  #23 §3.1 已给过理由）。若将来要给只读用户开写作，那是**新的能力需求**（沿用 map #1 的纪律：先找到真实需要），
  不是本票漏掉的一格。
- **读面不加编辑入口**：`/posts/:slug` 保持纯读面（#21 刚给正文面定稿），详情页**不做**「编辑这篇文章」链接。
  代价写明白：管理员改文章要多走两步（管理 → 文章 → 选中）。要加它是**对读面的一次改动**，
  该作为新决定提出来，而不是在本票里顺手塞进去。

## 5. 接口形状：表单 POST，不是 fetch / JSON

### 5.1 逐条对比

| 判据 | **表单 POST（选它）** | fetch / JSON |
| --- | --- | --- |
| 禁用 JS 也要能写 | 可用（#23 §5.1 把这条立成了硬约束） | 不可用 |
| CSRF | 复用 #25 的 L3：hidden input + 路由自己的 `preValidation` + `csrfField()`，**零新增机制** | 要再定一份 token 传输（请求头？）+ 第二处注入点 |
| 请求体解析 | 复用 `src/server.ts:122` 已注册的 urlencoded 解析器 | 要新增 `application/json` 解析器（第二个 content-type 面） |
| 失败呈现 | 400 就地重渲染 + `notice` 闭集（一处） | 要么页面自己渲染错误（第二套），要么返回 JSON——而 JSON 错误在浏览器里**不是**「显眼」 |
| 成功 | 302 PRG（#23 §4.1：刷新不会重复提交） | 需要一套前端状态机（无构建步骤下就是手写 JS） |
| 程序化调用 | 无来源头一律 403（#25 §2.1），本来就不是给脚本用的 | 同样受 L2 约束，**没有优势** |

### 5.2 顺带决定：**不做自动保存**

自动保存（边打字边写）只有两种实现：定时 `fetch` 写（需要 JSON 写接口 + 冲突处理 + 「保存中 / 已保存」的界面状态）
或整页定时刷新（会打断输入）。两者都要一套前端状态机，而收益是「不用点保存」。
**明确不做**：写入的唯一通道是用户按下的那个提交按钮。

> 这条同时是 [编辑器形态](https://github.com/Lkyloveaw/lkyloveaw-home/issues/34)（#34）原型的**边界**：
> 分栏实时预览可以有（客户端增强，不改写路径），但**若原型要求自动保存，那是对本节的显式修订**——
> 需要重新开一次决定（JSON 写接口的鉴权面、`action` 闭集之外的第二条写通道），不能在批次票里顺手加。

### 5.3 请求体与长度上限

- 请求体：`application/x-www-form-urlencoded`（既有解析器），**不做 multipart**（图片见 §5.4）。
- **正文上限【默认】256 KiB（UTF-8，约 8 万字）**，由**字段校验判 400**（文案说清是正文太长）。
  为什么必须有这条：Fastify 默认 body 上限是 1 MiB，撞上去是 **413**——而 413 没有站内文案、
  也不走「就地重渲染 + 保留输入」，用户会丢掉一整篇长文却看不到一句解释。
  字段上限**必须明显小于** body 上限，让用户撞到的是有文案的 400。
  （【默认】= 主理人替用户定的可一行推翻的值，沿用 map #20 的标记法。）

### 5.4 图片上传不在本票

[图片与静态资源落点](https://github.com/Lkyloveaw/lkyloveaw-home/issues/36)（#36）决定要不要上传、存哪、URL 长什么样。
本票只声明两条边界：

1. 图片上传（若做）**必须落在同一鉴权面**（同一 `requireAdmin` + L2 + L3），不新开一条写通道；
2. 「上传」今天**不是既有能力**：`src/server.ts:122` 只注册了 urlencoded，multipart 是**新增一个解析器**——
   这是 #36 的落点与代价，别在文章批次票里默认它已经有。

## 6. 失败呈现（照抄 #23 / #25，只列文章特有的三处）

| 情形 | 状态码 | 呈现 |
| --- | --- | --- |
| 校验失败（缺标题 / slug 冲突 / 正文超限 / 日期非法） | **400** | 就地重渲染 + `notice-bad` + **回填全部已填字段，尤其正文** |
| 对象规则拒绝（§7） | **400** | 同上，文案说清是哪一条 |

## 7. 本模块新增的对象规则（判定表里「这次具体改动能不能做」）

### 7.1 slug 必须在全部文章里唯一（现在就必须补）

- **事实**：`src/content.ts` 全文**没有**任何 slug 唯一性检查；`getPost()` 用 `find()` 取**第一个**命中
  （`src/content.ts:134-136`），排序是 date 倒序 → 同名时胜出的是日期较大的那篇；列表页会把两篇渲染成
  指向同一 URL 的两张卡片（研究 §1.3）。
- **规则**：创建与保存时必须判「这个 slug 是否已被**另一篇**占用（含草稿）」→ 冲突 **400** + 文案给出占用者的标题。
- **为什么是现在**：网页一开放写入，「人打错一个 slug」就从「不可能」变成「每天可能」，
  而后果是**静默地让一篇文章从站点上消失**。
- **归谁**：谁生成 slug（自动 / 手填）、发布后能否改 = **#32**。
  本票只要求**校验必须存在**，并附一条备查约束：老 URL 不能断是硬约束（研究 §5.1 第 1 条），
  所以「发布后允许改 slug」这条路**自带代价**（要么重定向表、要么别名表）——#32 若选它，要一并认领那份代价。

### 7.2 草稿过滤：两个具名函数，不是一个布尔参数

> ⚠ **已被修订（2026-10-17，#32 加回收站后）**：出口从**两个**扩成 **5 个具名读出口**
> （读面 2 · 管理台 2 · 回收站 1）**+ 回收站的 2 个动作**（`restoreArticle` / `purgeArticle`）。
> 原因是过滤维度从一维（草稿）变成两维（**草稿 × 已删除**）——布尔参数会有**四种组合**，
> 漏传一个就是泄漏。**纪律本身一字未改：出口一律具名，零布尔参数。**
> 新形状与逐出口的「谁调 / 滤什么」表见规格 [#48](https://github.com/Lkyloveaw/lkyloveaw-home/issues/48)。
> 下面这段是它的第一版，**留作理由记录**。

研究 §1.4 的推论是这张图最容易失守的一条：**任何绕过 `listPosts()` 的新代码都会漏出草稿**。规则：

- 内容层出口**只有两个**：`listPosts()`（读面：滤掉草稿，`src/content.ts:131`）与
  **新增**的管理台出口（**不过滤**草稿：列表 + 按 slug 取单篇）。
- **新出口必须是具名的两个函数**（如 `listPostsForAdmin()` / `getPostForAdmin(slug)`），
  **不许**做成 `listPosts({ includeDrafts: true })` 这种参数：布尔参数在调用点读不出意图
  （`listPosts(true)` 里的 `true` 是什么？），而草稿泄漏要靠 **diff 时一眼可审** 来防。
- 管理台出口**只允许在管理台路由里被调用**；写路径落地时**必须补一条草稿回归断言**（§9 第 2 条）——
  研究 §4 已核实：今天全仓**一条草稿断言都没有**。

### 7.3 写路径不得新增任何对外草稿 URL

草稿的语义是「不出现在任何列表 + 直链 404」（研究 §5.1 第 4 条，README 明文）。
所以编辑面里的预览（若做）**在管理台里渲染**（同一页面、同一鉴权），
**不许**为了「预览草稿」造出一条 `/posts/<slug>?preview=…` 之类的对外地址——
那是 map 迷雾里的「草稿的对外预览链接」，要单独决定。

### 7.4 写完立刻可见

写入成功后，**下一次 GET 就能看到**（读面与列表页都算）。这条在两种真源下都要成立：

- 真源是文件：内容层缓存按 `mtimeMs` 失效（`src/content.ts:113-129`）→ 写入必须让 mtime 变化
  （正常写文件即可；「写临时文件再 rename」同样要保证）。
- 真源是库：没有这层缓存，天然成立。

### 7.5 字段校验复用内容层的归一化，不许重写一份

| 校验对象 | 用哪个函数 | 不许做什么 |
| --- | --- | --- |
| `date` | `toIsoDate()`（`src/content.ts:46`） | 不许在路由里 `new Date(x)` 随手判 |
| `tags` | `toTags()`（`src/content.ts:57`） | 不许只按 `,` 切（既有实现还认全角 `，`） |
| `summary` | 留空则交给 `deriveSummary()`（`src/content.ts:68`） | 不许把派生值**写进**存储（它是派生字段） |
| `slug`（文件名形式） | `slugFromFile()`（`src/content.ts:40`） | 不许另定一套命名规则 |
| `draft` | **严格 `=== true`**（`src/content.ts:99`） | 表单提交的是字符串（`"true"` / `"on"`）→ **必须显式转换**，否则草稿静默变已发布（研究 §5.1 第 4 条点名的坑） |

同一条纪律的理由与 #25 §6 对 target URL 校验的理由完全一样：**重写一份 = 文件里被拒的值在网页上能存进去**。

  「文章的**实现票** ← 那张图的**具体批次票**」（外壳、`csrf.ts`、`requireAdmin`、`SITE_ORIGIN`、`role` 列）。
