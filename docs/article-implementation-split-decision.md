## 0. 结论一句话

**文章侧切 5 张票**，按「先能读、再能写、再管起来、最后收口」的纵深排：

```
① 引库与文档模型 + 搬库                             （不依赖另一张图）
      └─→ ② 管理台文章模块 + 富文本编辑器（写路径）   ← #37 #38 #39
              ├─→ ③ 回收站与修订
              └─→ ④ 图片与媒体层实现                  ← #41（规格）
                      └──────────→ ⑤ 文章侧验收收口  ← ①②③④
```

**5 张，不是 10 张**：文章侧的动作面比自管化侧小得多（那批要新建外壳、四个管理页、账密、备份、
目标增删改），这边只有「读 / 写 / 回收与修订 / 图片 / 收口」五件事。

## 1. 为什么不按文件切

判据是**垂直切片**：每张票交付一个**用户看得见的、能独立验收**的能力，合入后站点仍可用。
按文件切会得到「改了 `content.ts`」这种票面 —— 它既不能验收，也不能单独上线。

文章侧有几个**跨不动文件的耦合点**，正好说明为什么不能按文件切：

| 耦合点 | 为什么切不开 |
| --- | --- |
| `body` 的**格式** | 由编辑器形态决定（#34 选了富文本 → 结构化文档 JSON）。**表结构、渲染路径、编辑器三者必须同时就位**，换一半就是「存的东西没人能渲染」 |
| **schema 是安全边界** | 「schema 里不启用 raw HTML 节点」这条决定了读面渲染出的标签集是闭集（ADR 0006）。它同时管**读面**与**编辑器**，切给两张票就等于没人负责 |
| 读面出口与草稿纪律 | 研究 §1.4：**任何绕过出口的读取都会漏出草稿**。出口形状（按读者分组的具名函数）必须在**一次**改动里落定 |

## 2. 五张票的详细边界

### 票① 引库与文档模型 · 文章搬进 SQLite · 读面按 schema 渲染

**这是本批最大的一张，但它不可再分**（见 §1 前两条耦合点）。

**交付**

- 前端构建步骤 + WYSIWYG 依赖（[ADR 0006](adr/0006-frontend-build-step-for-richtext.md)）；打包产物进 `public/`，
  **闸门是精确路径匹配的白名单，新增静态资源要显式加进去**。
- **schema 定义**（ProseMirror / TipTap）：**不启用 raw HTML 节点** —— 这是 ADR 0006 里那条安全属性的全部依据。
- `articles` + `article_revisions` 两张表（沿用 `store.ts` 的「建表 + 就地补列」模式）。`body` 存**文档 JSON**。
- **首次导入**：`articles` 表为空 → `content/*.md` →（markdown-it）HTML →（schema）doc。
  导完文件被完全忽略、只打一行警告（与 `targets.json` 同一条规则）。
- **CLI 逃生口**（写在 `src/cli/` 下，`scripts/` 不进生产镜像）：**重导** `content/ → db`。
  **在票② 交付之前，它是唯一的编辑通道** —— 用户改文章的办法是「改文件 + 跑这个 CLI」，
  这比「搬完库之后文章彻底改不动」可接受得多。
- 内容层出口改成**按读者分组的具名函数**：本票只落**读面那一对**（滤草稿 + 滤已删除）。
- `/posts`、`/tags/:tag`、`/posts/:slug` 改从库读，**服务端**用 schema 渲染 doc → HTML。
- **修 `/posts/:slug` 的解码不对称**（`/tags/:tag` 解码、它不解码）。不修则「slug 允许中文」是假的。

**验收**

- `/posts/why-single-process`、`/posts/why-single-process`、`/tags/运维`、`/posts` 全部仍 **200**。
- 渲染产物**结构等价**：表格仍是 `<table>`、代码块仍是 `<pre><code>`、引用块仍是 `<blockquote>`。
  ⚠ **不承诺逐字节相同**（见 §3.1）。
- 草稿纪律不变：草稿不在任何列表、直链 **404**。
- `content/*.md` 不再是输入：改文件 + 重启，站点内容**不变**（只多一行警告）。

**不依赖另一张图** —— 它只动读面与库。

### 票② 管理台文章模块 + 富文本编辑器（写路径）

**交付**

- `/admin/articles`：GET（列表：标题 · slug · 日期 · 状态 · 标签 · 操作；`?edit=<slug>` 展开编辑面）
  + POST（hidden `action` 闭集：`article-create` / `article-save` / `article-publish` / `article-unpublish`）。
- **富文本编辑区**：内容以**文档 JSON** 落进 hidden 字段，照旧**表单 POST 到同一路径** + 302 PRG
  （#33 的接口形状不变；「禁 JS 可写」已由 #34 废掉，见 §3.2）。
- **草稿预览**在**同一页面内**渲染 —— **不许**在 `/posts/*` 下开任何预览入口（#33 §7.3）。
- 失败：**400 就地重渲染 + 必须回填正文**（一篇三千字因为 slug 重名被打回、正文却空了，
  是这个页面能犯的最贵的一次错）；`notice` 闭集。
- **对象规则**：slug 唯一性**跨草稿与回收站**（撞名 → 400，文案**给出占用者标题**，占用者在回收站时要明说）；
  标签名校验（名字即 URL，禁 `/`）；正文长度上限（#33 的【默认】256 KiB）。
- 新建默认**草稿**。

**硬依赖**：**[#37](https://github.com/Lkyloveaw/lkyloveaw-home/issues/37)**（`role` 列进闸门）·
**[#38](https://github.com/Lkyloveaw/lkyloveaw-home/issues/38)**（`requireAdmin` / L2 来源校验 / L3 token / `SITE_ORIGIN`）·
**[#39](https://github.com/Lkyloveaw/lkyloveaw-home/issues/39)**（管理台外壳 `layout()` / notice 闭集 / 400 就地重渲染形态）· 票①。

> **这三条边就是 #33 留下的那条「代理边」的正身**（§7）。

### 票③ 回收站与修订

**交付**

- 动作：`article-trash`（软删：置 `deleted_at`，不删任何行）· `article-restore`（清 `deleted_at`，
  **自动回到原状态**）· `article-purge`（**彻底删除**：删文章行 + 全部修订行，**必勾确认**）。
- 回收站视图（列表 + 还原 + 彻底删除）；**只做这两件事，想编辑先还原**。
- `?edit=<回收站里的 slug>` → **回列表 + 提示「它在回收站里，要先还原」**。
  ⚠ 这需要往 `notice` **闭集加一个键**（如 `article-trashed`）——闭集是刻意的（挡社工），
  所以**新增键本身是一次决定**，在本票的会话里做，不许实现随手加（§3.3）。
- **修订**：列表（时间 + 全文）与**退回某一版**（把那一版内容复制回当前文章，不移指针）。

**硬依赖**：票②（它交付页面与写通道）。

### 票④ 图片与媒体层实现

**交付**

- 上传通道（`multipart` 是**新增能力**，与 #33 §5.4 声明一致）· 媒体落点与 URL · 备份覆盖 · 孤图清理入口。
- 编辑器的**图片节点**（选中 → 上传 → 插入引用）。
- 落点与语义**全部由 [`docs/` 的媒体层规格]** 决定（那是 **[#41](https://github.com/Lkyloveaw/lkyloveaw-home/issues/41)** 的产出）。

**硬依赖**：**[#41](https://github.com/Lkyloveaw/lkyloveaw-home/issues/41)**（规格先出）· 票②（要有个能插图的编辑器）。

### 票⑤ 文章侧验收收口

**交付**

- 文章侧 e2e 的**最终形态**：把研究 §5.1 第 10 条点名的夹具改造做完（见 §3.5），补上草稿回归断言，
  并把「老 URL 不断」写成**常驻**断言而不是一次性检查。
- README 与文档一致（`CONTENT_DIR` 的说明、`docker-compose.yml` 那句注释、文章的真源口径）。
- **迁移演练**：从 Markdown 导入的完整走一遍 + 一条明确的回滚路径（整库备份）。
- 文章侧的真机项目（手机上看表格、浅色模式）**登记进 [#47](https://github.com/Lkyloveaw/lkyloveaw-home/issues/47)**，不另开票。

**硬依赖**：票①②③④。**与 [#46](https://github.com/Lkyloveaw/lkyloveaw-home/issues/46)（自管化侧的收口）同口径**：
若两者同时进行则**合并**；否则各管一侧，但收口判据（断言质量、README 一致、迁移演练）用同一套。

## 3. 本票新发现的问题（charting 时没看到）

### 3.1 MD → doc 的往返会改变渲染产物 —— 验收口径必须是「结构等价」

原型的转换器实测（我独立复现过，见 #34 的评论）：样本上「表格 5/5、围栏 2/2、引用块 1/1 保住」，
但**换一份输入，同样这三样全丢**（5 项丢 / 6 项），且**代码块的语言标注必然丢**（富文本里没有承载它的地方）。

所以票① 的「迁移后渲染不变」**必须**被写成「**结构等价**」而不是逐字节相同，并且**要先把这条口径写进断言**——
否则迁移后第一次跑 e2e 会被读成「迁移坏了」，然后有人去改断言迁就实现，而不是承认这是**已知的、被接受的**产物差异。

### 3.2 #33 §5.2 的「禁 JS 可写」已废，但它的**接口形状仍然有效**

#34 选了富文本 → 写需要 JS（该文档已就地加横幅）。实现时**别把整个 §5 一起推掉**：
`action` 闭集 · 同路径 POST · 302 PRG · 400 就地重渲染 · notice 闭集**全部仍然有效**。

### 3.3 `notice` 闭集要新增一个键（票③）

`?edit=<回收站里的 slug>` 需要一种新提示。闭集是刻意的（挡社工），所以新增键**是一次决定**，
放在票③ 的会话里做。**不许**在实现里随手加字符串（那样闭集就名存实亡）。

### 3.4 `content/` 的 `:ro` 挂载保留，但**语义变了**

它从「容器内只读的内容目录」变成「**首次导入的只读来源**」，而 `docker-compose.yml` 那句注释
还写着「目标清单与内容：改完重启容器即可生效」—— 票① 要改这句注释。**挂载本身不用动**（#32 已定）。

### 3.5 e2e 夹具改造与**顺序**冲突（票① 的真实约束）

研究 §5.1 第 10 条：e2e 夹具**直接往真实 `content/` 写文件**，不改成「写库/走接口」就是**假全绿**。

但票① 时**写接口还不存在**（它在票②）——所以票① 的夹具**只能直接写库**（调 store 层建行）
或**走票① 自己的 CLI 逃生口**。推荐**直接写库**：夹具的目标是造数据，不是验收写接口；
写接口的验收归票② 自己的断言。

### 3.6 票④ 依赖的 #41 是一张**规格票**，它自己还没做

`#41 规格：文章媒体层` 是 open 的。票④ 的阻塞边要挂在 #41 上，别让票④ 在规格没出来时开工。

## 4. 全局约束（每张票都适用）

沿姊妹图 §4 的八条，**其中三条在文章侧要改口径**：

1. **每张票合入后站点必须可用**。文章侧**没有**「全体重登」这类动作，但票① 有一次**不可见的真源切换**：
   从这一刻起改 `content/*.md` 不再影响站点 —— 这条必须写进票① 的票面与那句警告里。
2. **一票一次会话做完**。票① 是本批最大的一张；若某会话做不完，**当场再拆一票**，不在票内拖。
3. **断言必须先证明前提成立**（沿用 ADR 0004）。本批的上游决定里，`#33` 的 14 条与 `#48` 的断言清单
   **部分是未实测的**；落地第一件事是把本票要用的那几条跑成绿，**跑出与文档不一致的改文档**。
4. **「不引新依赖」在文章侧已被 ADR 0006 破例**（编辑面）。除 ADR 0006 明确的那一档，
   其余地方仍按原口径（内置优先）。
5. **`scripts/` 不进生产镜像**（`Dockerfile` 只 `COPY dist`）：票① 的 CLI 逃生口必须写在 `src/cli/` 下。
6. **失败要显眼不要静默降级**。
7. ⚠ **命令通道**：本批验收要跑 `npm run build` / `check:unit` / `check:e2e`。
   **若某张票的会话仍无可用命令通道，该票不得标记完成** —— 如实登记「代码已写、断言未跑」，缺口留给票⑤。
   （本条有现实依据：产出这些决定的会话里，`ops_bash` 与 `pwsh` 都曾被挡；`pwsh` 还额外会被
   执行策略挡在 `npx.ps1` 上，绕法是 `node --import tsx …`。）
8. 每张票只加**自己的、本地的**断言；不改别的票写的断言（收口归票⑤）。

## 5. 顺序与「每票可用」的关系

**硬依赖（写进阻塞边的就这几条）**

- ② ← ①：渲染器与表结构在 ①。
- ② ← **#37 #38 #39**（跨图）：管理台外壳、`requireAdmin`、CSRF 面、notice 闭集。
- ③ ← ②：回收站与修订是写通道之上的动作。
- ④ ← **#41**（规格）+ ②。
- ⑤ ← ①②③④。

**软约束（写在票面上，不写进阻塞边）**

1. **③ 与 ④ 都不阻塞彼此**，串行建议 ③ → ④（③ 更接近「把写路径用完整」）。
2. **④ 会再动票② 写的编辑器代码**（加图片节点）。② 的会话要知道：那是预期内的二次进入，不是返工。
3. **① 与 #45（整站视觉）都动 `public/style.css` 与正文渲染**：谁后合谁适配；
   ① 不改正文面的**视觉**，只保证渲染产物结构等价。
4. **⑤ 与 #46 若同时进行则合并**（§2 票⑤）。

**「每票可用」在本批的含义**

| 票合入后 | 用户能做什么 |
| --- | --- |
| ① | 站点读起来**完全一样**；改文章要靠「改文件 + 跑 CLI 逃生口」 |
| ② | **在网页上写、改、发**（这是本图目的地的达成点） |
| ③ | 误删能找回；改坏了能退回某一版 |
| ④ | 文章里能放图片 |
| ⑤ | 断言、文档、迁移演练全部对齐 |

## 7. 跨图代理边的**改指**（本票被点名的义务）

`#35 ← #27` 这条**代理边**的说明写着：「真正的落点是『文章的**实现票** ← 那张图的**具体批次票**』。
本票切出实现票之后，请把这条边改指具体批次（别让 #27 一直替它们挡着）。」

**本票照办**：删掉 `#35 ← #27`（#35 本次关闭），**改成**：

```
文章实现② ← #37（会话记录与角色基座）
文章实现② ← #38（写路径鉴权与 CSRF）
文章实现② ← #39（管理台外壳与只读页面）
```

**文章实现① 不挂任何跨图边** —— 它只动读面与库，**可以在管理台落地之前先做**。
这是一条有用的结论：**文章侧不必等自管化侧**。
