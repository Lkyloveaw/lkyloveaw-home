# 3. 公开契约不是内部结构

日期：2026-10-15
状态：已采纳

## 背景

`/api/status` 一开始是把内部汇总对象**原样** `JSON.stringify` 出去的。于是接口的形状等于
`ProbeTarget` / `TargetStats` / `ProbeResult` 这几个内部类型的形状：
`targets[].target.url`、`targets[].stats.samples`、`targets[].stats.upCount`……
前端也得跟着写 `item.stats.lastStatus`，**内部类型直接泄漏成了外部契约**。

后果有两层：

1. **改内部实现会改对外接口**。`store.ts` 里动一句 SELECT、`TargetStats` 加一个字段，
   公开响应就跟着变——没有任何人审过这个变化。
2. **不该出网的字段混在里面**。`url` 是内网资产地址，`expectStatus` 暴露判定口径，
   `lastError` 里甚至实测出现过**含口令的完整 URL 原文**。

而当时站点还没有鉴权，真实攻击者就是「任何能连到这个端口的人」。

## 决定

**`/api/status` 的形状由一个显式白名单投影 `toPublicSummary()` 单独决定**，放
`src/public-summary.ts`，`server.ts` 只负责调用它。

- 顶层**恰好 6 个键**；`targets[]` 由四层压平成**恰好 10 个键**；曲线点也逐字段挑。
- 判据：**每个字段都必须能回答「前端哪个 DOM 更新在用它」**，答不上来的就是内部细节。
- 新增字段的**默认结果是不出网**；要出网必须有人在投影里加一行——也就是有人**审过**。

配套：错误文案的脱敏放在**写入侧**（`src/sanitize.ts`），因为 `lastError` 与
`incidents[].error` 从同一列读，写一次三处都干净。

## 理由

**「要求登录」不能替代字段收敛。** 这是本决定最容易被误解的一点：
登录闸门之后，真实攻击者变成了「已登录的用户」。但：

- 内网站是多账号的，一个只读账号不该看到全部资产地址与判定口径；
- 已经写进历史库的错误原文会**一直**留在响应里，直到有人洗掉它；
- 日志、监控、浏览器缓存、分享截图都会带走这份响应——**收敛过的契约泄漏一次，代价小得多**。

两件事是**互补**的，不是替代关系：闸门管「谁能看」，投影管「看到什么」。

## 影响

- `src/public-summary.ts` 成为公开契约的唯一落点；改它等于改接口，要当心。
- 内部类型（`TargetStats` 等）可以自由演进，不再自动影响出网形状。
- 被删掉的字段里有两个是**有意的取舍**：`lastCheckedAt` / `upStreakMs` 在页面上仍可见，
  靠的是 SSR 渲染，所以「API 里没有」不造成功能回退。日后若要前端刷新它们，按白名单流程加回。
- **错误文案不再是原文**：超时/状态码这类**我们自己生成的**文案原样保留（信息量最大），
  运行时异常只留类别码，兜底是「探测失败」。排障能力略降，但换来的是不再泄漏 URL 与凭证。
- 前端若依赖被删字段会静默失效——本次实测就抓到了 `public/status.js` 读 `item.target.id`
  而投影已把它压平。**改契约必须同时检查前端**。
