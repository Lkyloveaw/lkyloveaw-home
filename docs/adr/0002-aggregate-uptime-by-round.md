# 2. 可用率按「轮次」聚合，而不是按记录

日期：2026-10-14
状态：已采纳

## 背景

面板的「整体可用率走势」一开始是按记录的 `at` 精确分组求平均。
看起来对，实际是错的：同一轮里各目标并发发起，`at` 相差几毫秒，于是**每个分组只包含 1 个目标**。

结果是曲线在 0% 和 100% 之间跳——一个每个点都只有 1 个样本的「比例」，不构成任何信息。

## 决定

给每条记录加上 **`roundAt`**（该轮探测的起点），整体可用率按 `roundAt` 分组聚合。

## 理由

「可用目标占比」只有在分母覆盖**全部目标**时才有意义。
每轮共用一个时间戳，是让这个分母成立的最小改动。

## 影响

- 表结构新增 `round_at` 列，并对旧库做就地迁移（补列 → 回填 → 建索引，顺序不能反，
  否则 `CREATE INDEX ... (round_at)` 会在旧库上直接报错、服务起不来）；
- 迁移来的旧数据每轮只有 1 个目标，其 `1/1` 会画成 100%。因此聚合时**只保留
  `total >= 当前目标数` 的轮次**：宁可少几个点，也不给出含义不一致的曲线；
- 这条影响是实测出来的——旧库里 87 条单目标轮混进新曲线就是锯齿。
