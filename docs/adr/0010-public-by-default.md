# 10. 站点默认公开：登录只保护需要身份的路径

日期：2026-10-30
状态：已采纳（取代 [登录闸门判定表](../login-gate-decision-table.md) §2 的白名单范围）

## 背景

2026-10-15 的闸门决定把**整个站点**关在登录后面：首页也渲染系统名与可用率，所以「只锁面板」等于白锁。
2026-10-30 用户改主意：这是一个个人站，内容本来就是给人看的；匿名访客应该能读文章、看可用性面板，
登录只在**真的需要身份**的地方出现（管理台、账户页、写路径）。

## 决定

站点**默认公开**：

- 匿名可读：`/`、`/posts`、`/posts/:slug`、`/tags/:tag`、`/status`、`/about`、`/api/status`、
  `/media/*`，以及静态资源；
- 需要登录：`/admin*`、`/account`、`/password`、`/logout`；
- 闸门的**默认拒绝**保持不变：没登记的路径仍然要登录，新增管理路由不会意外公开；
- 公开页命中时仍解析会话：有效 cookie 渲染用户菜单，否则渲染「登录」入口（`next` 指回当前页）。

## 理由

1. **内容的价值在读者，不在身份**：文章与状态面板是站点的主体，要求登录等于默认没有读者。
2. **身份只对「能改东西的人」有意义**：管理台与写路径本来就另有资格守卫（`requireAdmin`），
   闸门只需要拦住它们，不需要顺带把只读面一起锁上。
3. **默认拒绝的形状不能动**：白名单从「精确路径」扩到「精确 + 三条动态前缀」，但兜底仍是拒绝——
   这是当初那条决定的真正价值，换的是名单内容，不是失效方向。

## 后果

- **`/status` 页面会向匿名访客显示目标 URL**（内网地址）。JSON 投影仍不含 `url` / `expectStatus`；
  若要把页面上的地址也收回去，应改面板渲染，而不是把 `/status` 重新关进闸门。
- 匿名访客能看到公开面的完整内容，包括草稿语义不变（草稿仍不在列表、直链 404）。
- 旧书签/爬虫拿到的不再是 302，而是真实页面；`next` 校验与 API 401 分流只作用于受保护路径。
- E2E 的会话失效探针从 `/status` 改为 `/account`（否则「未登录 302」断言会恒真/恒假）。

## 备注

- 实现落点：`src/auth.ts`（公开名单与判定）、`src/views.ts`（匿名登录入口）、`src/csrf.ts` + `src/server.ts`（`pathname` 上下文）。
