# 0008：系统可用性区分最新探测、缺测和异常事件

日期：2026-10-24。状态：采用。对应用户批准的第一轮可用性修改。

`generatedAt` 是页面取数时间，不证明探测仍在运行。增加每目标 `lastCheckedAt`、`upStreakMs`、`staleAfterMs`，用于时间显示和新鲜度判断。三档探测结果不变，新鲜度叠加显示；默认阈值为三个当前探测间隔加该目标超时。当前配置改变后，历史缺测也按当前阈值解释。

`/api/status` 顶层增加 `windowStartAt`，固定图表横轴；目标白名单由 10 项变为 13 项。事件保留原有安全字段，新增 `lastSeenAt`、`endedAt`、`durationMs`、`outcome`，只提供页面展示需要的事件信息。目标 URL、凭据、状态码配置、样本内部字段仍不出 API，错误继续通过 `forOutput`。

原 `docs/api-status-fields-decision.md` 中「时间字段没有消费者所以不输出」的判断被本次实际刷新需求取代；白名单与默认不出网原则保持。

连续可用截止最后确认；长缺测断开。失败连续记录合并为事件，下一次成功为恢复记录；遇缺测则标记未知。事件展示起止为采样时刻，不宣称故障恰好在该秒发生。窗口相交、当前启用目标过滤先于最近 8 起限制。

曲线对全窗口按时间分桶，保留首尾和极值，额外保留每段异常/缺测的边界及相邻有效点。同桶出现多次短故障时也必须断开；为此，频繁抖动时允许点数超过普通包络的上限。图例明确趋势是采样，平均指标单独使用全量数据。前端取数时同步所有指标，取数失败后继续按经过时长判断新鲜度；目标清单变化提示刷新，避免在旧卡片上拼出新汇总。
