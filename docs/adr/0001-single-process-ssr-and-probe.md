# 1. 单进程同时承担渲染与探测

日期：2026-02-18
状态：已采纳

## 背景

站点有两件事要做：渲染内容页（事情分享）和周期性探测内网业务系统。
最初考虑过前端直接 `fetch` 内网地址，看似最省事。

## 决定

**渲染与探测放进同一个 Node 进程**，用 SQLite 单文件存历史。

## 理由

探测无法放在浏览器端，这是硬约束：

1. 同源策略挡掉跨域响应，除非每个内网系统都配 CORS（不现实）；
2. 前端探测是「有人打开页面才探」，凌晨那段历史永远是空白；
3. 站点若部署在内网之外，浏览器根本碰不到 `10.x` 地址。

既然必须有服务端，前后端分离在此规模下只有成本没有收益：多一套构建、多一个容器、多一层联调。
SSR 直接出完整 HTML 还有额外好处——首屏不等 JS、无 hydration、整站一份依赖树。

面板的自动刷新用一小段原生 `fetch` 局部更新数值，不引框架。

## 影响

- 站点不能部署为纯静态（放弃了 GitHub Pages 之类的方案）；
- 曲线与页面渲染都在服务端，且是内联 SVG，因此**禁用 JS 也能看到完整面板**；
- 面板数值每 30 秒刷新，~~曲线随页面刷新~~——**已被后续决定取代（2026-10-23）**：
  曲线也随 30 秒重绘，见 [`docs/chart-redraw-decision.md`](../chart-redraw-decision.md)。
  仍然成立的是「服务端内联 SVG，禁用 JS 也能看到完整面板」。
