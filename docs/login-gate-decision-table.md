# 登录闸门判定表

本文件是「给整个站点加登录闸门」这张票的产出：**路径 × 未登录行为**的可落地判定表。
它决定 `src/server.ts` 里那道闸门怎么挂、放行谁、每种未登录请求回什么。

票：<https://github.com/Lkyloveaw/personal-wiki/issues/3>

## 1. 闸门挂在哪一层

**结论：一个全局 `onRequest` 钩子。**

已实测（本机 Fastify + `@fastify/static` 注入验证）：

- 全局 `onRequest` 钩子**会**拦到 `@fastify/static` 提供的静态资源（`/style.css` 命中钩子）。
- **与注册顺序无关**：先 `register(static)` 后 `addHook`，和先 `addHook` 后 `register(static)`，钩子命中清单完全一致。
- 在钩子里直接 `return reply.code(302)...send()` 会短路，静态处理器不再执行。

这条实测推翻了一个常见假设——「静态资源不走业务钩子」。因此：

- 闸门**能**用一个全局钩子覆盖「整个站点」，不必逐路由声明，满足 Destination 的硬约束（首页也在未鉴权渲染系统名与可用率）。
- 但静态资源**必须显式写进白名单**，否则登录页自己会拿不到 `/style.css`，渲染成裸 HTML。

逐路由声明被否决：它要求每个新增路由都记得挂闸门，漏一个就重新变成「未鉴权泄漏」。全局默认拒绝、白名单显式放行，才是失败安全的形状。

## 2. 白名单

白名单是**精确路径匹配**，不是前缀匹配。理由见 §4。

| 路径 | 未登录行为 | 放行理由 |
| --- | --- | --- |
| `/login` | 放行（GET 出表单、POST 校验） | 否则永远无法登录 |
| `/healthz` | 放行，回 `200 {"ok":true}` | `Dockerfile:41-42` 与 `docker-compose.yml:25-30` 的 HEALTHCHECK 打它**且不带凭证**；一旦要求登录，容器永久 unhealthy，`restart: unless-stopped` 下反复重启 |
| `/style.css` | 放行 | 登录页自己要用样式；且实测它在钩子覆盖范围内 |
| `/status.js` | 放行 | 登录页与面板共用；内容是只读的抓取逻辑，不含数据 |
| `/favicon.ico` | 放行 | 浏览器自动请求，要求登录只会产生噪音 302 |

白名单里**没有** `/`、`/posts`、`/posts/:slug`、`/tags/:tag`、`/status`、`/about`、`/api/status` —— 这些正是本次要关上的面。

## 3. 未登录响应的两种形态

**判据：看请求要的是 HTML 还是 JSON，而不是看路径前缀。**

| 请求特征 | 未登录响应 |
| --- | --- |
| 页面（`Accept` 含 `text/html`，或未声明 Accept） | `302` → `/login?next=<原路径>` |
| API（`Accept` 含 `application/json`，或路径以 `/api/` 开头） | `401` + `{"error":"unauthorized"}` |

**为什么不能一律 302**：`public/status.js:59` 用 `fetch('/api/status', { headers: { accept: 'application/json' } })` 拉数据。若回 302，`fetch` 默认跟随跳转，拿到的是登录页的 **HTML**，`r.json()` 抛错。

更值得记一笔的是**当前会怎样**：`status.js:64-66` 的 `.catch()` 是**静默失败**——注释写着「面板保留上一次数据，比显示错误更不打扰」。所以会话过期后面板会**悄悄冻结**，用户看着一屏旧数字，没有任何提示。这正好撞上本仓库的既有取舍「**失败要显眼不要静默降级**」（map Notes）。

→ 因此 401 是必要条件，但**不够**。`status.js` 的那段静默 catch 必须一并改成显眼失败（这是「登录闸门」落地时的连带改动，不是新票）。本次只定判定表，实现时同步处理。

## 4. `next` 回跳的安全性

**结论：`next` 只接受站内相对路径；无法确认就丢弃，回退到 `/`。**

已实测的攻击面（Node `URL` 解析 + 注入验证）：

| 输入 | 是否逃出站外 |
| --- | --- |
| `//evil.com/path` | ★ 逃出（协议相对） |
| `/\evil.com/path` | ★ 逃出 |
| `\/evil.com` | ★ 逃出 |
| `////evil.com` | ★ 逃出 |
| `https://evil.com/path` | ★ 逃出（绝对 URL） |
| `/status`、`/status?x=1#frag` | 安全 |

判定式（拒绝优先，白名单化路径校验）：

```
next 必须以单个 '/' 开头
且第二个字符不是 '/' 也不是 '\'
且解析后 origin 不变
且最终落点必须在已知路由白名单内
否则丢弃 → 回退 '/'
```

**为什么还要加「落点必须在已知路由白名单内」**：仅靠形状判断会放行 `/任意乱串`，用户登录后被送到 404 页。登录成功应该回到真实存在的地方。

**CRLF 注入**：实测把带 `\r\n` 的值塞进 `Location` 头，Node 的 HTTP 层直接抛 `ERR_INVALID_CHAR`，请求变 **500**，头没被注入。所以不存在头注入，但会变成难看的 500 —— 判定式里显式拒绝控制字符，是为了让它优雅回退而不是 500。

## 5. 连带影响（落地时必须一起改，否则验收是假的）

`scripts/e2e-check.mjs` 是本次改动的**验收面**，但它现在**假设全站匿名可访问**：

- `e2e-check.mjs:83-101` 逐个断言 `/`、`/posts`、`/about`、`/status`、`/api/status`、`/healthz`、`/style.css`、`/status.js` 都是 `200`。
- 整个脚本**没有任何登录步骤**。

闸门一挂，这些断言会成片变红。所以落地时必须同时：

1. 让 `e2e-check.mjs` 先登录拿 cookie，再带着 cookie 跑原有断言（保持原有覆盖不缩水）；
2. **追加**未登录断言：每个受保护路径未登录 → 页面 302 / API 401；
3. 保留 `/healthz` 匿名 200 的断言（容器健康检查的回归护栏）。

这是本票推导出的**新事实**，charting 时没看到。

## 7. 边界

- 本票**只定判定表与落点**。会话 cookie 的载荷/过期/密钥由「会话维持」票定；`users` 表与口令校验由「账号存储与口令校验」票定。
- 登录页表单字段名与 POST 路径在此定为 `/login`（POST），供那两张票对齐。
- HTTPS 是后续需求，`Secure` 属性必须能关、默认关（map Notes 第 9 条）。
