# 个人设置设计（已确认）

> 后续修订：用户另行要求个人头像及网站徽标，原「不添加头像」边界由[身份图片设计](2026-10-23-identity-images-design.md)取代，其余约定保持。

## 目标

为普通登录用户提供集中管理个人偏好与账户的页面，入口放在导航栏用户胶囊展开面板中。页面只展示设置项、必要的状态和提交反馈，不添加功能介绍、维护指南或实现说明。

## 方案

推荐升级现有 `/account` 页面：菜单中的「修改口令」改为「个人设置」，页面标题也改为「个人设置」。复用原有登录保护、账户表单和主题逻辑，原有链接继续有效。

另一个方案是新增 `/settings` 并保留独立账户页。它会把主题和账户操作拆到两个页面，在目前只有少量设置项的情况下增加跳转，因此不推荐。

用户于 2026-10-23 确认此方案。

## 页面内容

| 区域 | 设置项 | 交互 |
| --- | --- | --- |
| 账户 | 用户名、账户角色 | 只读展示；不开放自行改用户名或权限 |
| 外观 | 主题：跟随系统 / 浅色 / 深色 | 选择后立即生效，沿用当前浏览器记忆；无保存按钮 |
| 安全 | 当前口令、新口令、确认口令 | 沿用原有验证与提交；保留「修改口令后，其他设备将退出登录」提醒 |

主题在胶囊菜单中继续提供快捷切换。在个人设置页修改主题时，两处选择器同步更新。主题仍只保存在当前浏览器，不新增跨设备同步或用户偏好数据表。

## 入口与布局

- 胶囊菜单顺序：身份 → 个人设置 → 管理后台（仅管理员）→ 主题 → 登出。
- 管理员与只读账号都可以访问个人设置；未登录仍回到登录页，登录后返回 `/account`。
- 沿用账户页的简洁布局，不增加顶栏导航项、文章侧栏或管理侧栏。
- 桌面与移动端使用同一页面，设置行在窄屏自然换行；保持现有键盘操作和触摸目标。

## 边界

- 修改口令的 CSRF、失败回显、成功跳转、当前浏览器保持登录及其他设备退出语义不变。
- 不添加昵称、头像、个人简介、通知开关等没有对应网站能力的设置。
- 不添加字号、字体或主题自定义，延续当前统一排版与三态主题约定。
- 不添加设置教程、自动保存说明、后端或浏览器存储说明等页面附注。

## 验收

- 胶囊菜单可通过悬停、键盘和点按进入个人设置，两种账户角色均可用。
- 个人设置页正确展示账户信息、主题选项及改密表单。
- 两处主题选择器同步，刷新和跨页后保留选择；存储不可用时仍可在当前页切换。
- 原有 `/account` 登录回跳与改密成功、失败、会话失效检查通过。
- 无 JavaScript 时仍可修改口令，不展示无法操作的主题选择器。
- 页面没有新增解释性附注，桌面及窄屏不溢出。
