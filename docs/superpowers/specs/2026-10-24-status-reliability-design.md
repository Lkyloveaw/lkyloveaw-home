# 系统可用性第一轮修正

用户已要求实施上一轮评估中的第一轮修改：统计可信度、刷新一致性、缺测提示、异常事件及数字文案。沿用卡片布局，不加入筛选器、移动端折叠或新的监控依赖。

- 曲线覆盖完整最近 24 小时。按时间分桶保留首尾、极值和失败断点，不能截取窗口最早 120 条；无探测的长间隔断线。图例明确采样口径，不拿降采样后的平均值冒充窗口平均。
- 每次刷新同步四项汇总、状态、时间、曲线、格带及事件列表。格带是最近 56 次，统计值是最近 24 小时。
- 数据新鲜度独立于 up/degraded/down。阈值为三个当前探测间隔加目标超时；超过阈值显示「数据过期」，不计入当前可用或当前异常。连续可用只累计到最后一次确认，缺测后重新起算。首页摘要采用相同判据。
- 顶部第四项改成「当前异常系统」。最近 24 小时的连续失败合并成事件，展示首次记录、已确认持续时间、恢复或持续/待确认状态；缺测不能宣称一直故障，也不能假定已恢复。
- SSR 与自动刷新一致。新增 API 字段仅限页面实际使用的时间、新鲜度和事件字段；继续显式投影和错误脱敏，URL 等内部配置不出 API。
- 百分比固定两位小数；页面取数时间与各目标探测时间明确区分。保留原延迟统计口径，文案说明它包含所有已收到的 HTTP 响应，延迟口径拆分留待后续。

选择局部修正现有 SSR + 原生 JS；整页定时重载会打断阅读，替换图表库不能修正统计口径，因此均不采用。
