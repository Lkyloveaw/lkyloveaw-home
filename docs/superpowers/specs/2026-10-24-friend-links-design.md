# 导航徽标与全站友联

日期：2026-10-24
状态：已确认；2026-10-24 用户授权按本设计实施。

## 目的与范围

放大导航栏左侧徽标，改善大屏观感；在所有公开内容页的页脚上方显示同一份友联，管理员维护一次即可全站生效。
本次是既有站点上的小范围功能扩展，沿用 SSR、SQLite、媒体上传和现有样式体系。

## 已确认的行为

- 导航徽标由 24px 调为桌面 40px、手机 32px，网站名称字号保持现状。
- 友联使用图文卡片：图标、网站名称、一句简介；宽屏并排，窄屏自动换行。
- 图标上传到本站；没有图标时显示网站名称首字。
- 在“管理台 → 站点设置”集中新增、编辑、删除和排序。
- 点击友联在新标签页打开，保留本站页面。
- 初始列表为空，整个友联区隐藏；添加真实条目后再显示。

## 方案与取舍

用户选择后台统一维护，配置文件方案因此不采用：后者实现更少，但改动仍依赖编辑文件和部署。
展示直接复用 `src/views.ts` 已有 `layout()`，这是满足单处维护的现成入口，无需逐页复制，也无需引入新的模板系统。

实现方案：

- 使用同一 SQLite 中的 `friend_links` 表保存条目，字段为稳定 id、名称、网址、简介、可选媒体文件名和排序值。
  现有 `settings` 只接受字符串或整数，独立记录表可沿用现有设置表单，避免为列表扩展通用设置类型。
- 站点设置页新增独立友联管理区；排序采用数字顺序，同序按稳定 id 排列，新项默认追加。
- 名称和网址必填，简介和图标可留空；建议名称 1–60 字、简介 0–200 字、网址最长 2048 字符，仅接受 HTTP/HTTPS。
- 在共用布局中渲染一份友联区，位于正文容器之后、原页脚之前，宽度与页面公共容器协调。
- 显示范围为首页、分享列表、标签列表、文章详情、系统可用性、关于。
  管理台、个人设置、登录和错误页不显示；“公开”沿用现有内容读面的访问规则。
- 保存后下次页面请求即生效，无需重启；已打开的页面刷新后更新。
- 复用现有上传格式和大小限制；友联图标计入媒体引用，避免被孤图清理误删。
  更换或删除条目只解除原图片引用，文件仍交由现有显式清理流程处理。
- 外链使用 `target="_blank"` 和 `rel="noopener noreferrer"`；名称、简介等文本按现有规则转义。
- 复用管理员权限、来源校验及 CSRF 守卫；无需新增依赖。

## 验收

- 管理员可完成增删改和排序，刷新及重启后仍保留；普通账号不能写入。
- 新增、修改、排序或删除后，六类公开内容页展示同一份结果，列表为空时整区消失。
- 验证上传图标、无图标首字、图标更换、以及孤图清理保留有效引用。
- 拒绝非法网址、超长字段及不符合现有规则的图片；失败时保留可修正的表单内容。
- 检查桌面与手机的徽标尺寸、卡片排布，浅深主题、键盘操作及无 JavaScript 的基本使用。
- 运行针对友联存储、路由权限与渲染的行为检查，再运行仓库规定的验证命令。

## 本次边界

不加入自动抓取 favicon、友联申请审核、远程可用性探测或新的页面权限规则。
部署继续使用裸机与 systemd；本设计不涉及部署变更。
