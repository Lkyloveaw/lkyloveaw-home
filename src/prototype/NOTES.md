# 编辑器形态原型（抛弃式）：三个变体，争的是「编辑区那一块」

- 票：[#34 编辑器形态：纯 Markdown 文本域 / 分栏预览 / 富文本](https://github.com/Lkyloveaw/lkyloveaw-home/issues/34)（map：[#30 文章后台](https://github.com/Lkyloveaw/lkyloveaw-home/issues/30)）
- 分支：`prototype/editor-shape` —— **抛弃分支**。主分支上不留这里的任何一行（§9）。
- 一条命令：`npm run prototype:editor` → <http://127.0.0.1:3100/prototype/editor>

---

## 1. 这份原型要回答什么

**问题**：这个站的文章编辑器该是哪种形态 —— 纯 Markdown 文本域 + 服务端预览、分栏实时预览，还是富文本？

判据是两把尺子：① 在**中文长文 / 表格 / 代码块 / 图片**这四件事上的**手感**；② **无构建步骤**下的**实现代价**。

**为什么走 UI 分支（同路由多变体 + 底部悬浮切换条），不是单文件逻辑原型**：问的是「编辑器长什么样、哪种形态手感对」，
三个候选本来就是同一个页面的三种结构。草稿 → 发布的状态模型是 #32 的地盘，不在这张票里。
「实现代价」也不靠手感判——它从原型代码里数出来（§7）。

**为什么用抛弃式路由（技能里的 sub-shape B）**：编辑器**还没有宿主页面**（管理台 map #20 未落地，`src/server.ts` 里没有任何 `/admin`），
没有任何既有页面能装下它 —— 空壳页面又会把「分栏在 900px 下被挤成两栏」这类真问题藏起来。

**为什么是独立原型进程，而不是往 `src/server.ts` 里加一条原型路由**（这是与上一张原型票 #21 不同的地方，值得说清）：

| | 挂进产品进程（#21 的做法） | 独立原型进程（本次） |
| --- | --- | --- |
| 产品文件改动 | `server.ts` / `auth.ts` / `views.ts` 都得改 | **只有 `package.json` 一行**（`prototype:editor`） |
| 登录闸门 | 要么改白名单，要么先建号登录 | 不需要：它不挂闸门（原型要随手点开就比） |
| 「误合并进产品」 | 要事后清理，漏一处就带着原型路由上线 | **结构上不可能**：不存在可合并的产品改动 |
| 代价 | 贴着真站同端口 | 另一个端口（3100）、没有闸门 |

它能贴着真实排版密度，靠的是**复用产品的 `layout()` 与 `public/style.css`**（真的页头、真的页脚、真的 900px 版心），
预览用的是**真的 markdown-it**（与 `src/content.ts` 逐项同参）与**真的 gray-matter** —— 只有「编辑区那一块」是假的。

## 2. 三个变体在争什么（结构不同，不是配色不同）

| | 变体 | 第一等公民是谁 | 主操作 | 需要 JS | 预览来自 |
| --- | --- | --- | --- | --- | --- |
| `A` | 纯文本域 + 服务端预览 | **一次提交** | 写完点「预览」 | 否 | 服务端 markdown-it |
| `B` | 分栏实时预览 | **打字的过程** | 打字（停 350ms 自动同步） | 是 | 服务端 markdown-it（防抖 POST 回填右栏） |
| `C` | 富文本（所见即所得） | **最终长相** | 直接看着写 | 是 | 不适用：屏幕上就是最终形态 |

三者的分歧在第一等公民是谁：A 是「我提交的那一版」，B 是「我正在写的那一句」，C 是「读者将看到的样子」。

## 3. 怎么跑、怎么看

```bash
npm run prototype:editor          # → http://127.0.0.1:3100/prototype/editor
```

- **底部悬浮条**切变体：`?variant=A|B|C`；`←` `→` 键也能切（焦点不在输入框时才生效 —— 按技能的规矩，编辑区里不抢方向键）。
  左右箭头本身就是链接，所以**关掉 JS 也能切变体**。
- **切变体会把当前正文带过去**（`sessionStorage`）：不然每换一版你就得重贴一次。关掉 JS 就带不过去 —— 那是 A/B 的诚实降级，页面上也写着。
- **C → 别的变体**会强制先过一次「存回 Markdown」，并把损失报告摊开给你看之后才让你走：富文本没有无损出口，这一点不该被藏起来。
- **四个测试点按钮**（长段落 / 表格 / 代码块 / 图片）跳到样本里对应的位置 —— 近似定位（按行号比例），长文里会偏。
- **状态面板**在编辑区上方，每次切换/提交后重算：变体、主操作、需不需要 JS、预览来自哪、正文行数字数、
  编辑区实测宽、上次往返毫秒、预览字节、以及 **front-matter 的真实解析结果**（含「未知键被丢弃」与「`draft: "true"` 字符串不算草稿」这两条真语义）。
- **换样本**：直接改 `src/prototype/editor-sample.md`，刷新即可。它是真文章为底 + 两节标注过的加料：
  前五节逐字取自 `content/2026-02-20-uptime-metrics.md`；`原型加料 ①` 是中文长段落，`原型加料 ②` 是一张真图片
  （`src/prototype/assets/sample-chart.svg`）—— 补的正是原文缺的两样（`content/` 两篇真文章**零图片引用**，且都只有 ~1.2k 字，见 #31）。

## 5. C 的损失报告实测：富文本存回 Markdown 到底丢了什么

拿**真实渲染结果**（6036 字节 HTML，即 C 编辑区里实际看到的内容）原样存回，与样本原文逐项比：

| 项目 | 样本原文 | 存回的 Markdown | 判定 |
| --- | --- | --- | --- |
| front-matter（6 键元信息） | 有 | 无 | **丢** |
| 表格行 | 5 行 | 5 行 | 保住 |
| 代码块围栏 | 2 个 | 2 个 | 保住 |
| 代码块语言标注 | 有（`json`） | 无 | **丢** |
| 图片引用 | 1 个 | 1 个 | 保住 |
| 引用块行 | 1 行 | 1 行 | 保住 |

**这张表要正确地读**——它一半是结论，一半是我的自白：

- 真正过不去的是**语义标注的落点**：front-matter 六键（slug/title/date/tags/summary/draft）在富文本里**没有位置**，
  只能另做一套表单；代码块的 `json` 语言标注在 `contenteditable` 里也没有承载它的地方。这两条换谁写转换器都一样。
- 「5/6 保住」有**开卷考**的成分：这个转换器是我照着这份样本写的。样本里没有内联样式、嵌套列表、脚注，
  所以它看起来体面。**硬骨头用例**（`scripts/prototype-editor-verify.sh` 里那段）证明了这个天花板：
  内联样式被登记为丢、嵌套列表被登记为拍平、不认识的标签（`figure`）被拍平。
- **真机跑出来的真 bug（值得记一笔）**：第一版的 `<p><img></p>` 里的图片被**静默吞掉** —— 存回 Markdown 后图片没了，
  而屏幕上不会有任何提示。这是这类转换器最危险的一类损失：不在明面上，在于你根本不知道它没了。
  修法是容器/行内分开渲染（`renderContainer()`），并把「不认识的标签」也改成保留内容。
- 换来的是：C 这一版必须 JS（与仓库「禁用 JS 也要能读能写」正面冲突）、真源从 Markdown 变成 HTML、
  以及一个**成品要用 ProseMirror / TipTap 这类库、因而要引入依赖与构建步骤**的反向转换器。

## 6. 未验证 / 缺口（诚实登记）

- **没有真机浏览器 PoC**。所有验证都在 HTTP 层（curl + 产物断言），我没有目视过渲染结果，
  **没有测窄屏断点，也没有测 `prefers-color-scheme: light`**（原型用的是产品 token，深色是默认）。
- **客户端 JS 只做了静态检查**：防抖实时预览、切换带正文、键盘 `←`/`→`、跳到测试点、C 的工具栏与「存回 Markdown」
  这几段都**没有在浏览器里点过**（这个会话里没有浏览器）。它们的存在性在页面上断言过，交互行为**未验证**。
- `execCommand` 已被标准废弃，各浏览器行为可能不同（工具栏是脚手架，不参与评形态）。
- 跳到测试点是**近似定位**（按行号比例），长文里会偏。
- 状态面板里的「编辑区实测宽 / 往返毫秒」由浏览器填报：**curl 环境里量不到真数**，请在你自己屏幕上读。
- 转换器是原型级：嵌套列表压平、内联样式丢弃、表格没有列对齐语义、脚注/定义列表/HTML 块不认识。

## 7. 三个变体的代价（原型页面上也写着同一份）

| | 实现代价 | 手感代价 |
| --- | --- | --- |
| `A` | 一个 `<form>` + 一次 `md.render()`：**0 行 JS、0 新依赖** | 预览永远是上一次提交的；每次预览整页刷新，**光标与滚动位置都丢**；长文里代价被放大。护城河：禁用 JS 也可用 |
| `B` | 一次防抖 + 一个返回 JSON 的端点；**没有第二个渲染器**（仍走服务端 markdown-it） | 必须 JS；每敲一次键盘一次请求；**900px 版心下两栏各约 420px**，中文长段落与宽表格会被挤；关掉 JS 退化成 A |
| `C` | `contenteditable` + `execCommand` 能出第一版手感；**贵在反向**：HTML → Markdown 转换器（这一版我手写了 342 行原型级转换器）——成品要上库与构建步骤 | **必须 JS**；真源从 Markdown 变 HTML；front-matter 六键无落点；**存回 Markdown 有损**（见 §5） |

备选路（没走，写下来是因为它是 B 真正贵的那条）：把渲染搬进浏览器 —— 要么 vendored 一份 markdown-it 浏览器包
（**两份渲染器 = 两处会漂移的真源**），要么上构建步骤。这两条都与仓库既有取舍冲突，所以 B 选了「防抖 POST + 服务端渲染」。

## 8. 落选的东西去哪了

按技能 §6：**整套变体是这次决定的主源**，所以它落在**抛弃分支** `prototype/editor-shape`，主分支只留最终决定。

**主分支上不留**：`src/prototype/`（6 个文件）、`scripts/prototype-editor-verify.sh`、`package.json` 里的 `prototype:editor`。

## 9. 清理

主分支**不需要 revert 任何东西**（这些文件从没进过主分支）。要清的是这条分支：

```bash
git branch -D prototype/editor-shape                 # 本地
git push origin --delete prototype/editor-shape      # 远程（决定落进主分支之后再做）
```

产品页面从来不知道 `?variant=` 是什么）。
